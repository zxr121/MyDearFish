# 上下文预算与故障自愈

[English](context-budget.md) | 中文

陪伴会话会随着每一轮不断变长。要让它不变长到“说不出话”，有两个接缝：压缩必须在请求还落在可靠范围内时触发；失败的一轮必须看得见、能恢复，而不是对着同一个超大会话无限重试。

## 为什么旧的预算从不压缩

`deepseek-flash` 和 `deepseek-v4-pro` 声明了 1,000,000 token 的上下文窗口，适配器默认 `maxTokens` 为 256,000。于是压缩压力是 `min(1,000,000 × 0.8, 1,000,000 − 256,000 − 65,536)`，约 67.8 万 token。一个长到约 30 万 token 的 QQ 社交会话因此从未压缩过。2026-10-23 那天，这个尺寸的一轮回复以 `TRANSPORT` 在十六秒内失败五次，而同一秒约 2,900 token 的裁判调用成功；当天上午 23.7 万 token 的冷请求是成功的。结构上的缺陷是这个永远够不到的触发点，而不是少了一次重试。

## 触发与保留

鱼层设置两个压缩默认值：`thresholdRatio: 0.15` 和 `retainRatio: 0.05`。在 1,000,000 token 窗口下，15 万 token 触发，最近约 3.7 万 token 原文保留，其余变成摘要检查点。摘要请求本身携带可压缩前缀加上配置的摘要输出，因此仍低于失败过的尺寸。声明的上下文窗口不改：那是模型能力，而触发点属于部署策略。

profile 层应用同样的两个值，已有 profile 无需重装 bundle 就能生效；新安装从鱼 bundle 拿到出厂默认。

## 重置一个会话

已经超大的会话没法靠压缩修复：摘要器会把刚刚失败的那个大请求原样重放一次。QQ 桥提供 `POST /dsh-qq-bridge/session-reset`，参数是目标会话 id。路由会释放活着的 agent 句柄，清掉那个房间的待看批和失败计数，并把带后缀的新会话 id 记进 `$DSH_HOME/qq-bridge-sessions.json`。下一条消息会在这个新 id 下新建会话；旧会话目录留在磁盘上作为备份。设置页在目标旁边提供同一个动作的按钮。

宿主重启时会读取覆盖文件，所以会话 id 跨重启保持稳定。主人私聊房使用同一套机制；手填的 `目标会话` 如果正指向被重置的会话，会自动改到新 id。

## 失败可见性

一轮回复以 `turn/end` 和原因收尾。桥原先只处理 `completed`，忽略 `error`，180 秒后只留一条超时日志。现在它会立刻记下失败 code 和消息，按目标累加连续失败数，并清掉待发；完成的一轮会清零。

同一目标连续失败三次后，桥会暂停这个目标的自动回复十分钟，新消息只入缓存，不再往坏会话里追加，同时给主人私聊发一条系统提示。提示是以 `【大肥鱼·系统】` 开头的运维文字，不是她在说话。状态路由按目标暴露 `故障.连续`、`故障.最后说`、`故障.最后At`、`故障.暂停到`，以及主路对应的失败记录。设置页显示失败行并提供重置按钮。

## 运维说明

桥配置仍在 `$DSH_HOME/qq-bridge-config.json`；会话覆盖记在 `$DSH_HOME/qq-bridge-sessions.json`；旧会话留在 DSH 会话目录下。重置一个房间不会删除任何记录，但下一轮没有最近的本地聊天原文；她在 fish-mind 里的长期经历不受影响。
