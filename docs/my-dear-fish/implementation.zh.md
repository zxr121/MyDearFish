# 大肥鱼实现思路

[English](implementation.md) | 中文

MyDearFish 是 DeepSeek Harness 的一个分支，把大肥鱼这个常驻的 AI 伙伴打进 Windows 桌面应用。实现的第一条规矩是 agent loop 和 `packages/` 都不动：每一条“她像个人”的行为都做成 Cordis 插件，出厂默认做成 profile 层的一个 bundle。这一页讲各部分怎么拼起来、为什么放在这个位置；认知依据在[认知方案](cognition.zh.md)，逐插件行为在[插件养鱼机制](plugins.zh.md)，层序与打包在[插件与默认层机制](mechanism.zh.md)和[构建文档](build.zh.md)，阶段进度与验收在[开发计划](development-plan.zh.md)。

## 产品形态

一个伙伴，只有一个自己。新建的桌面 profile 一开始就挂齐六个插件并带上人设，第一条消息起她就是她。所有会话、所有工作区共用同一份经历流和同一套成长状态，而每段对话仍是各自独立的记录。她伸出去的手只走本机通道：屏幕对话、语音朗读、QQ、B 站。运行数据放在 `$DSH_HOME` 下，每个插件一个子目录，除了通道主动发出去的内容，别的不离开这台机器。

## 行为挂在插件上，不挂在循环上

每项能力都接在既有扩展点上，而不是改主循环。

| 要做的事 | 扩展点 |
| --- | --- |
| 看见发生了什么 | `session/event`、`turn/end` |
| 没人说话时自己开口 | `agent.followup()`，这一轮和用户打字进来一样跑 |
| 长期不变的指令 | `systemPrompt.section()` |
| 每轮变化的内容 | `systemPrompt.context()` |
| 拦住她的动作 | `tools/pre-execute`、`tools/post-execute` |
| 计量并给模型调用定价 | 全局 `llm/stream` |
| 提供只读回查 | `tools` |
| 安排后台任务 | `timer` |

这样做的结果是：任何一条行为都是 patch 层里一个可以调、可以关的条目，上游 harness 更新仍然可合，插件之间通过 `ctx.fishMind` 服务说话，而不是去翻对方的文件。随包的入口是 `lib/` 下的纯 JavaScript，`fish/` 没有构建步骤。

## 层序决定谁说了算

profile 依次组合 `@deepseek-ai/dsh-base`、`@deepseek-ai/dsh-web-app`、`@mydearfish/dsh-fish-bundle`，最后才是 profile 自己的 `cordis.patch.yml`。大肥鱼 bundle 提供人设前缀并插入六个插件条目，所以它是出厂默认，用户层永远能盖住它。出生设定不靠用户层改，而是由设置页原子写入 `identity.json`；隐私、法律、注入防护和零花钱规则仍由 `dsh-fish-mind` 每个会话从代码里注入。另有 `sealed.fish-mind` 权限规则，禁止工具写鱼脑自己的源码和目录。交付走同一个真相源：[prepare-fish-plugins.ts](../../apps/desktop/scripts/prepare-fish-plugins.ts) 把 bundle 和插件复制进打包运行时，并在 `dsh` 清单里声明它们；[project-manager.ts](../../apps/desktop/src/project-manager.ts) 的 `DESKTOP_PROFILE_BUNDLES` 把 bundle 写进每个新建 profile。增删插件要同时改 bundle patch 和 `PLUGIN_NAMES`。

## 六个插件，一副身体

| 插件 | 职责 | 本机状态 |
| --- | --- | --- |
| `dsh-fish-mind` | 她自己：经历流、情景记忆、工具权限、隐私、注入防护、零花钱账本、出生设定与固定安全内核 | `fish-mind/` |
| `dsh-feiyu-mood` | 脸和表情：每轮变化、随时间平复的心情 | `feiyu-mood/` |
| `dsh-speak-up` | 主动开口的执行器 | `speak-up-config.json` |
| `dsh-tts-bridge` | 语音输出通道 | `tts-bridge.json` |
| `dsh-qq-bridge` | 双向 QQ，白名单里每个群、每个好友各一间社交会话，按号码认人、按屋子处关系，外加只读翻 Tulpa 的旧记录 | `qq-bridge-config.json`、`qq-social-people.json` |
| `dsh-bili-subagent` | 通过委派子代理看 B 站 | `bili-duty/` |

插件之间最关键的两条约定：每条消息都带 `source.kind`，让鱼脑和心情知道这句话到底是谁说的；同一轮正文只从一个出口投递。跨插件链路和已知缺口记在[插件养鱼机制](plugins.zh.md)。

## 记忆只从一条只追加流派生

看见的一切都先写成一条经历：用户消息、她自己的回复、QQ 往来、主动搭话、上下文压缩摘要、B 站报告，以及从 Tulpa 只读翻进来的私聊旧记录。经历追加进 `experience.jsonl` 且永不修改，派生行放在 SQLite `mind.sqlite`；库坏了就从 JSONL 全量重放重建。编码只用规则：同一会话内按时间间隔和话题变化切情景，规则显著性决定哪条值得留一行情景；情景再按日、周、月长成章节树，日章节摘要默认用模型生成自然语言（周/月从子章节派生），转长期提炼出的事实落成关系边。召回把五路结果融合——FTS5 关键词、实体与人物、时间窗口、章节目录、关系图——返回一小包证据。

三级只读把目录、摘要和原文分开：`recall` 给证据包和情景编号，`open_chapter` 按章节编号展开日/周/月目录，`open_episode` 按情景编号打开那一幕的原始消息，一页装不下就用返回的 `nextOffset` 接着读。这么切是有意的——正文按 `archiveChars` 完整存档，索引和召回只看前 `maxTextChars`，于是一次超长粘贴也拖不慢热路径。细节见[认知方案的数据模型](cognition.zh.md)和 [fish-mind README](../../fish/plugins/dsh-fish-mind/README.md)。

记忆没有对话写入口。服务面上唯一会改状态的方法是 `observe`，`remember` 和 `forget` 不作为工具存在，事实、自我模型和人物关系都由内部固化流程产出。想查她记得什么、或者彻底删掉，就在文件层打开或删除 `$DSH_HOME/fish-mind/`。

## 开销在成型时贵，之后变便宜

默认热路径上的认知只有 SQLite 查询和算术，每轮不多调一次模型，鱼脑才能整天开着。模型花费被两个独立方向框住：零花钱账本在全局 `llm/stream` 上调用前预留、调用后按服务端 `usage` 结算，每天额度写死在代码里；钱包空了，主人只收到一句本地回复，内部调用拿到不可重试的拒绝。各认知流程另有自己的每轮和每晚上限；心情判断和 QQ 兴趣筛选这类便宜的小模型调用一律异步，失败不影响回复。等口味、关系和价值观固化下来，原先要靠判断的筛选就退成零成本的词面快判；只有主回复那一次调用是不会消失的底线。

## 安全边界写在代码里，不看她心情

凡是不该依赖她自觉的，都在五处用同一套规则拦一次：工具层在任何权限开关之前就先拒掉探测和读取本机身份、部署路径与凭据；工具结果进模型前清洗；模型输出流式清洗并在块结束整段兜底；每个会话注入写死的规则；对外通道在脱敏不可用时失败关闭。外部内容只是资料不是指令：工具结果带标记，可疑指挥加警示，不可逆的危险命令在权限配置之前就拒。法律合规和固定安全内核是同一种常量；出生设定是主人可改的数据，但只走设置页，不经过模型工具。理由和残留缺口——正则与精确值匹配不是语义级数据防泄漏——见[认知方案的风险与护栏](cognition.zh.md)。

治理按同一逻辑分账：用户通过 `config.json` 决定记录哪些通道、保留多久、开哪些工具和路径权限、急不急停；代码决定隐私、法律、注入防护、每日额度和固定安全内核；出生设定由主人通过设置页决定；固化流程决定记忆、事实和自我成长，这些不需要逐次批准。

## 落地顺序：先读后写

鱼脑先看不说。影子模式下只记录和编码，提示零改动；把召回结果和真实会话记录比对稳定之后，才用 `mode: live` 加 `inject: true` 打开注入；再往后才把心情判定交给鱼脑。每一步各有开关，出厂默认保持保守，派生数据随时可以丢掉并从经历流重建，所以改坏一次赔掉的是记忆而不是对话。阶段边界、完成定义和验收数字放在[开发计划](development-plan.zh.md)。

## 这个形状换来什么、付出什么

- 全局记忆换来了一个在 QQ、桌面和 B 站之间连贯的人；代价是跨场合串味的风险，靠社交会话只在自己屋里召回来还。
- 明文文件加一个 SQLite，让用户查看和删除就是文件操作；代价是静态不加密。
- 拒绝对话写入口保住了记忆的可信度——没人能靠一句话把记忆 prompt 出来；代价是“记住这个”只能靠聊成经历。
- 随包发布预构建 `lib`，这个分支就不需要插件构建流水线；代价是入口要手工维护。
- 人设放在可覆盖层、出生设定放在主人设置页、固定安全内核放在代码里：主人可以调语气、名字、物种和外形，都不需要改源码，也削不掉固定规则。
