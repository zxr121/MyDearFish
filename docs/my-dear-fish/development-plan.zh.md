# 大肥鱼认知系统开发计划

[English](development-plan.md) | 中文

这份文档给接手开发的人看：只记录做到哪了、下一步做什么、怎么算做完。设计理由和生物学依据在[大肥鱼认知方案](cognition.zh.md)，这里不重复。方案与代码冲突时，以代码和本文的验收记录为准，再回头修正方案。

## 怎么用这份文档

先看“当前快照”和里程碑表确认进度；开工时按对应阶段的清单做，逐条满足完成定义后才改状态；离开前更新变更日志，并按接手清单留下报告和回滚说明。

- 看进度：当前快照给出基线，里程碑表给出每个阶段的状态、日期和负责人。
- 开工：阶段清单是可执行的最小任务集，完成定义是唯一的“做完”标准。
- 交接：交接物写清下一阶段需要的数据、开关和已知坑，没有交接物不算完成。

## 阶段 0：影子运行

### 目标

让鱼脑先看不说：监听真实桌面会话，把经历写进 SQLite，但不动提示、不注入记忆、不调模型。跑满一周，用数据证明该记的都记下了，库也能重建。

### 开工清单

- [ ] 新建 `fish/plugins/dsh-fish-mind`：`package.json`（`type: module`、`main: lib/index.js`、版本 `0.1.0`）、`cordis.patch.yml`、`lib/index.js`、`README.md` 和 `tests/`。
- [ ] 注册 Cordis 服务 `ctx.fishMind`，先暴露 `observe`、`recall`、`remember`、`forget`、`state`、`plan`、`reflect` 七个方法；除 `observe` 外都返回空结果或“未启用”。
- [ ] 配置放在 `$DSH_HOME/fish-mind/config.json`，默认 `mode: shadow`、`inject: false`、`retentionDays: 90`；坏配置回退默认值并写日志。
- [ ] 建 `$DSH_HOME/fish-mind/mind.sqlite`：WAL、`busy_timeout=5000`、`user_version=1`、单写队列；建 `experiences`、`episodes`、`facts`、`people`、`intentions`、`affect_log`、`predictions`、`self_model`、`chapters`、`sleep_runs` 和 `experience_fts`。
- [ ] 同时写一份只追加的 `fish-mind/experience.jsonl` 作为重建源；SQLite 损坏时从它恢复。
- [ ] 监听 `session/event` 和 `turn/end`：只收用户消息、助手回复、QQ、主动搭话和 B 站报告；跳过子代理、插件注入和 `runtime-context`。
- [ ] 每条经历写来源、可信度、会话、角色和敏感字段清洗结果；密码、密钥、身份证、银行卡和精确住址直接丢弃并计数。
- [ ] 中文 FTS 用字符二元组预处理加 `unicode61`，查询走同一处理器；单字查询退回 `LIKE`。
- [ ] 写重建命令或测试：清空派生表后从 `experience.jsonl` 全量重放，条数和哈希与原库一致。
- [ ] 在 `fish/bundle/cordis.patch.yml` 挂载 `fish-mind`，并把它加进 `apps/desktop/scripts/prepare-fish-plugins.ts` 的 `PLUGIN_NAMES`；先默认只观察。
- [ ] 指标写进 `fish-mind/diag.log`：每日事件数、丢弃数、库大小、写入耗时 p50 和 p95、异常。
- [ ] 插件自带测试覆盖来源映射、敏感字段清洗、二元组查询和重建；用 `node --test` 跑，不引入构建步骤。

### 完成定义

- [ ] 连续一周真实使用，事件数与 DSH 会话记录逐日对齐，缺失为零。
- [ ] 同一份 `experience.jsonl` 重建出的 SQLite，经历条数、FTS 命中数和哈希全部一致。
- [ ] 影子模式对提示零改动：同一会话开启前后系统提示逐字节相同。
- [ ] 每轮额外写入的 p95 不超过 10 毫秒，主对话无可感延迟。
- [ ] 敏感字段抽样检查为零泄露，日志里不出现原文。
- [ ] 关掉插件后 DSH 正常启动，`.dsh` 下只多出 `fish-mind/` 目录。

### 交接物

- [ ] 一份一周影子报告：事件量、来源分布、失败与修复、数据库体积。
- [ ] 阶段 1 的召回语料：至少 100 个真实回合和人工标注的相关记忆，脱敏后存放。
- [ ] 回滚说明：`mode: off` 与移除 bundle 挂载两种方式，以及各自的影响。

## 阶段 1：情景记忆

### 目标

把经历变成可召回的情景，并让模型在需要时能想起来。这一阶段只做记忆，不碰情绪、自我和主动；所有产出都要能在开关关闭后完整退回旧记忆插件。

### 开工清单

- [ ] 情景切分：按时间间隔和话题变化切段，参数进配置；每段写 `episodes`，标题和摘要留到阶段 2 补。
- [ ] 编码：先实现规则版 S 公式，相似度用词元和实体重叠，不调模型；阈值 0.35，低于阈值的经历只保留原文。
- [ ] 四路召回：FTS5、实体与人物、时间窗口、图扩展；每路取前 20，融合取前 6；没有强相关时返回空。
- [ ] 工作台：最多 5 槽、约 900 字，槽带类型、来源和置信度；空的时候明确写“本轮没有可靠记忆”。
- [ ] 注入：稳定段 `fish-mind-protocol`（order 89980），动态段 `fish-mind-workspace`（order 910），由 `inject` 开关控制。
- [ ] 工具：实现 `recall` 和 `remember`；`forget` 只做软删，硬删只接受用户发起。
- [ ] 兼容：旧记忆插件保留 `remember` 名字并转发给鱼脑；旧 JSON 只读导入；接管后关闭旧召回。
- [ ] 基准：100 个真实回合回放，遮住后续内容，输出 precision@6、来源准确率、虚假记忆率和延迟。
- [ ] 计量：每轮记录检索耗时、注入字数、模型调用和 token；热路径默认零调用。
- [ ] 测试覆盖融合排序、无记忆不硬编、来源标签、注入开关和回滚旧插件。

### 完成定义

- [ ] 30 条历史问答的召回准确率不低于 70%，并且能给出大致时间而不是背原句。
- [ ] 100 回合回放的 precision@6 不低于 0.7，来源准确率不低于 0.9。
- [ ] 诱导问题集的虚假记忆率不高于 5%，没发生的事明确说没印象。
- [ ] 工作台注入不超过 1200 字；端到端 p95 增量不超过 50 毫秒；热路径零模型调用。
- [ ] 回滚开关能恢复旧记忆插件，旧数据不被修改或删除。

### 交接物

- [ ] 基准报告：语料版本、基线数字、失败样例和下一步修正建议。
- [ ] 默认配置表和迁移说明：旧记忆 JSON 如何导入、如何关闭、如何验证。
- [ ] 阶段 2 的睡眠任务清单，附第一阶段真实数据暴露出的问题。

## 本地开发与验证

先确认基线能跑，再改插件。仓库命令以根 `README.md` 和[构建文档](build.zh.md)为准；下面的命令都在仓库根目录执行。

| 目的 | 命令 | 说明 |
| --- | --- | --- |
| 安装依赖 | `pnpm install --frozen-lockfile` | 需要 Node 24 和仓库固定的 pnpm 版本。 |
| 构建并运行 | `pnpm run build` 后接 `pnpm dsh web` | 从源码启动 Web UI，默认 `127.0.0.1:3080`。 |
| 插件测试 | `node --test fish/plugins/dsh-fish-mind/tests/*.mjs` | 新插件用 Node 自带测试，随包的 `lib` 不需要构建。 |
| 文档门禁 | `pnpm run test:docs` | 检查配对、链接、换行、预算和 README 规则。 |
| 静态检查 | `pnpm run lint` | 与推送钩子使用同一套检查。 |
| 打包预检 | `pnpm run package:desktop:win:x64:unsigned --check` | 验证插件和 bundle 被正确注入，不产出安装包。 |

- 新插件只放在 `fish/plugins/dsh-fish-mind`，入口是 `lib/index.js`；运行时加载 `main`，没有构建步骤。
- 挂载插件要同时改 `fish/bundle/cordis.patch.yml` 和 `apps/desktop/scripts/prepare-fish-plugins.ts`，漏一处会打包失败或启动缺插件。
- 文档先改中文再同步英文，跑 `pnpm run verify-translation-pairing --write docs/my-dear-fish/development-plan.md`，再跑 `pnpm run test:docs`。
- 合并前至少跑构建、插件测试和打包预检；打包细节和产物位置见[构建文档](build.zh.md)。

## 验收数据怎么留

每个阶段完成后，把“命令、日期、commit、结果”写进交接物；只写结论不写来源的数字一律不算。语料放仓库外或脱敏后入库，不上传对话原文。

| 指标 | 阶段 0 和 1 的门槛 | 数据来源 |
| --- | --- | --- |
| 事件完整率 | 零丢失，逐日对齐 | 影子日志与 DSH 会话记录 |
| 库可重建 | 条数和哈希一致 | 全量重放测试 |
| 召回精确率 | 前 6 条不低于 0.7 | 100 回合回放，人工标注 |
| 来源准确率 | 不低于 0.9 | “你怎么知道的”探针 |
| 虚假记忆率 | 不高于 5% | 未发生事件的诱导问题集 |
| 延迟 | 影子 p95 不超过 10 毫秒；阶段 1 增量不超过 50 毫秒 | 本地端到端基准 |
| 成本 | 热路径零调用；睡眠每晚不超过 8 次、3 万 token | token 账本 |

- 语料来自真实历史，遮住后续内容后再让系统召回，标注由第二个人复核。
- 每个数字记录复现命令和 commit；指标变差时先修召回和工作台，不要加新层。
- 基准在本地跑，只保存脱敏摘要和统计，不保存原始对话。

## 协作约定

- 小改动直接提交 `master`；跨阶段功能用 `feat/fish-mind-phase-N` 分支，一次只做一个阶段。
- 提交信息用 `feat(fish-mind):`、`fix(fish-mind):` 或 `docs:` 前缀，一个提交只做一件事。
- 每次改动完成即提交并推送，公司电脑从 `master` 同步。
- 行为、配置或数据格式变化必须同时更新中英文文档和配对记录。
- 不提交密钥、真实聊天原文和用户隐私数据；测试语料脱敏后才能入库。
- 热路径不加模型调用；后台任务分批让出事件循环，单批不超过 20 毫秒。
