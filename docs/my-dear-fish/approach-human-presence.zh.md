# 群聊像人、功能补齐与精力预算

[English](approach-human-presence.md) | 中文

这份文档回答三个问题：她在群里为什么还不像人、怎么改、钱怎么花得少还自然。设计依据来自人类多人对话的研究，落地位置是 `dsh-qq-bridge` 和 `dsh-fish-mind` 现有代码；还没实现的条目会标明，不把计划写成现状。

## 一句话

让她在群里真的“待着”：所有消息先进房间账本，再由一张有梯度的参与决定（不看 / 短应 / 接话 / 起话）；余额当作会累的精力，累了就少说、短说，而不是机械地闭嘴；省下来的钱来自不重复判断、不重复喂上下文、让缓存命中，而不是把回复压成敷衍。时间感从 0.2.96 起步：想接但此刻不该接的话先挂住，等屋里安静了她再回来补上，而不是当场硬回或永远错过；0.2.97 起话头能落盘、跨重启，等待也从十分钟放宽到几小时。

## 她现在的七个断点

| 断点 | 现在的行为 | 代码位置 |
| --- | --- | --- |
| 听见等于被挑中 | 判断模型每轮最多挑 12 条进 `watch`，没挑中的她当没看见 | `host.js` 的 `关注上限`、判断提示词 |
| 只记得自己挑过的 | 只有被挑中的消息进一小时缓冲，下一轮的“上下文”也只从缓冲里取 | `并入社交缓冲`、`带上下文` |
| 只有说和不说 | 判断结果是 `reply: true/false`，没有“应一声”“发个表情”“这句不用回”的中间档 | `判.reply === true \|\| 必须回` |
| 不分谁在对谁说 | `对别人说` 只认回复和 @，按名字起头对第三个人说话识别不到 | 群消息入库处 |
| 群里没有她自己 | 心情判断跳过 `qq-social-*`，内在生活提示对社交会话返回空，主动搭话排除社交房 | `dsh-feiyu-mood`、`dsh-fish-mind`、`dsh-speak-up` |
| 节奏机械 | 连发固定 450 毫秒一条，拆句规则固定 | 发段延迟 |
| 没有社交电量 | 只有全群每小时 / 每天次数，没有“这间屋刚说太多，先歇会儿” | `主动每时`、`该歇口气` |

这七条里，前三条是同一个根：桥把“看见”和“接话”绑成了一次判断。人不是这样，人先一直在场，再决定这次要不要开口。

## 人类在群里怎么待着

| 机制 | 研究结论 | 她该怎么用 | 对应改动 |
| --- | --- | --- | --- |
| 参与框架 | Goffman：在场的人分“被认可的参与者”和“旁观者”，旁观者也在听 | 没被挑中的消息也要进账本，她可以后文接上 | 房间账本 |
| 话轮分配 | Sacks / Schegloff / Jefferson：当前说话人可以用名字、@、眼神选出下一位 | 按名字和回复链判断这句话在对谁说 | 收件人判断 |
| 共同基础 | Clark & Brennan：对话靠双方不断确认“我们说的是同一件事” | 她接话前先看这条是不是已经被别人答了 | 已答标记 |
| 责任分散 | Darley & Latané：人越多，越少有人觉得自己该出手 | 群里没人问她时，沉默是正常的，不必每批都回 | 参与梯度 |
| 参与不平等 | Nielsen 90-9-1：绝大多数人只看不说 | 她的发言应该远少于阅读 | 社交电量 |
| 沟通适应 | Giles：人会向对方的语速、用词靠拢 | 已有的群语感和风格贴合保留，但只在真开口时用 | 现有 |
| 修复 | Schegloff：听错、没听清时用“啊？”启动修复 | 对方回“？”或“你说啥”时，换一句话重说，不重复原句 | 修复回合 |

## 在场：账本、收件人、梯度

### 房间账本

每间群 / 好友在内存里保留最近 240 条消息、最多一小时，字段只有 `id`、时间、说话人、QQ 号、正文前 120 字、回复目标、是否在叫她。硬过滤仍然先跑：关掉的房间、不理的人、她不聊的话题、纯广告，不进账本。账本不落盘，重启就清空；长期记忆仍由鱼脑按经历流负责。

账本解决三件事：判断模型看到的是“这间屋最近在聊什么”，而不是“上一轮我挑了什么”；她可以接上一个自己没被挑中、但后文变得相关的话题；别人已经答过的问题不会再问她一遍。

### 收件人

每条消息标一个收件人：`她`、某个具体的人、`大家`、`不确定`。判断依据依次是：回复链指向谁、有没有 @ 谁、开头是不是“名字，”“名字你……”这样的称呼、句子里有没有“你觉得呢”。只在开头八个字内认名字，避免正文里随口提到一个人就被当成在叫他。

标成“对别人说”的消息不主动插话，除非同时叫了她。两半都已在桥里落地（0.2.88）：回复、@ 和按名字起头的称呼都能把消息标成对别人说；这类消息同时记进房间账本，后文聊到相关的事她接得上。

### 参与梯度

判断模型不再只回“接 / 不接”，而是回一个档位：

| 档 | 行为 | 成本 |
| --- | --- | --- |
| 0 不看 | 只记账，不进视线 | 零 |
| 1 短应 | 一个表情、复读、或一句二十字以内的反应 | 判断这一次调用就够，不再调回复模型 |
| 2 接话 | 正常一轮回复 | 判断 + 回复 |
| 3 起话 | 主动开一个新话题 | 回复 + 主动额度 |

档位 1 已落地（0.2.90）：判断模型在 `watch` / `reply` 之外可以给一句 `short`（2~12 字），桥先清洗（去引号、拒绝 @ / 链接 / 括号解释、2~20 字），再直接发进群，不调回复模型；被直接叫到、问她本人、查好感度、私聊、目标房间歇着 / 只听 / 试运行、同一句十分钟内刚说过，都退回正常回复。`社交.短应` 关掉就全部走完整回复。

档位 1 是省钱的关键：群里大量消息只需要“嗯”“确实”“哈哈”或一张表情，以前每条都要再调一次回复模型；现在判断模型顺手给一句短反应，这笔钱就省掉了。档位 0 和 1 都要真的允许发生，否则她还是那个每句话都接的人。

### 已答与沉默

群里有人回复另一条还没判的消息时，桥在消息进待看之前就把被回复的那条划掉（她本人被叫到的、或同一人自己接着说下去的不划），不再问她。她开口后把此前积累的消息一起划掉这一步还没做，留到线程分组那一轮一起处理，避免现在把还在长的话题误伤。

### 心情只读

0.2.91 起，心情插件注入的 `feiyu-mood` 上下文不再被聊天提示过滤器筛掉：她带着当下的心情进群，提示里只有一句状态，并明确要求别把这句话照念出来。心情插件本来就跳过 `qq-social-*` 会话的判断，所以群聊和好友私聊不会改变心情，只有和主人的对话会让心情涨跌。

### 回复串

0.2.92 起，上下文按「回复谁」连成串：回复和判断要带旧话时，先补齐被引用那条所在的串，再用最近的闲聊填满原来的条数预算（回复 20 条 / 2400 字，判断 12 条），最后按时间排好。她自己发出的每一段都记下真实消息 id，别人后来回复她时能把整串接回来。预算没有变大，只是把位置让给更相关的话。

### 节奏抖动

连发两段之间的停顿不再固定 450 毫秒，按上一条的长短和一点随机落在 0.4~1.2 秒：长句后停得久一点，短应后快一点。主人私聊和社交会话共用这套节奏，读起来不像定时器。

### 节奏

群里的回复延迟不再固定：按消息长度和情绪给 0.6 到 1.6 倍的抖动，最短不低于 0.8 秒；连发之间留 0.4 到 1.2 秒；对方连发时先等最后一条。字数越多，拆成两条的概率越高，但一条能说完就不拆。

### 社交电量

0.2.93 起，每间屋按最近十分钟别人的发言量记一个热度：20 条以上算话密，主动额度收到六成；40 条以上算刷屏，收到三成；每小时 / 每天至少留一轮。人不会在大家正聊得热闹时硬插话，这条也顺手省钱。被叫、问她本人、主人说话和好友私聊不走这个额度，`社交.电量` 关掉就只看固定话量。热度看的是屋里别人的动静，不是她自己说了多少：连说频率另有上限，跟着屋子的节奏收才像人。

### 修复回合

0.2.94 起，有人回“？”、“你说啥”、“没听清”、“什么意思”，而这条又是私聊、回复她或 @ 她、离她上一句不到十分钟时，桥跳过判断，把她那句原话带进回复轮，要求换一种说法重说：不原样复读、不只回“啊？”，也别道歉一长串。听着像没听清的问号本来就该答，这一轮省下一次判断。十分钟外、没冲她来的问号照常判断；只听不说和歇着时照旧不开口。`社交.重说` 关掉就全走判断。

### 时间感（0.2.96 起）

现在的她只活在“当下这一批消息”里：一批消息进来，判断一次，几秒内回或者不回；主动搭话也是按时间和情绪掷骰。人不是这样——看见了可以晚点回，忙完补一句“刚在忙，你前面说啥”，隔天还会回头问“你那个面试咋样了”。这件事不需要新模型常驻，靠已有的房间账本、鱼脑记忆和主动额度就能做。

分三步，前两步已经落地：

1. **留话头（已完成 0.2.96）**：判断挑中了、她也有话想说，但冷却、电量、额度、静音、屋里正忙把她拦下时，不硬回，把这条记成“悬着的话”留在房间里；只听不说、歇着和关掉的房间不记。默认十分钟后、屋子安静两分钟、她再次在场时，用一次便宜判断决定要不要补一句；补的时候带上原话和最近上下文，可以自然说一句刚看到，不必解释去了哪。额度与主动话量共用，每屋同时最多挂三条，挂过三倍时间或跨天就丢。
2. **迟到回话（已完成 0.2.97）**：挂住的话头落到本机的 `qq-bridge-threads.json`（`DSH_HOME` 下，只存原话、说话人、时间与挂住原因），挂住、放下、别人接过、补完、删房间都会同步；重启后当天的话头直接读回来，跨天和残缺的记录丢掉。`社交.迟到分钟` 上限放到 360，下班前没接上的话，隔几个小时屋里安静下来也能补；她回来时先看这些，再决定先补哪一条。
3. **隔天回头问（后续）**：从鱼脑里能回头问的事实（面试、旅行、宠物、考试、答应过的事）生成带时间的由头，替换主动搭话的随机掷骰——有由头的搭话更像人，也更少白花钱。

守卫：过期时间、把握门槛、每屋上限；这段时间别人已经把话接完的，她直接放下，不补一条重复的；补话不追问、不复读、不发“在吗”。设置页能看到每间屋悬着的条数和上次回头的时间，`社交.迟到` 关掉就完全不补。迟到的回话在验收里单独抽查，过时、接错人、重复补都算失败。

## 精力：余额就是力气

### 三层

| 层 | 含义 | 数据 |
| --- | --- | --- |
| 储备 | 还能撑多久 | `availableCny / dailyGrantCny` |
| 今日消耗 | 今天已经用掉多少力气 | `spentTodayCny / dailyGrantCny` |
| 昼夜节律 | 这个点在不在状态 | 本地小时 |

### 六档

| 档 | 条件（G = 每日额度） | 主动 | 探索 | 回复 |
| --- | --- | --- | --- | --- |
| 精神很好 | 余额 ≥ 1.5G 且今天用了不到 40% | 正常 | 可以 | 正常 |
| 正常 | 余额 ≥ 0.8G | 正常 | 可以 | 正常 |
| 有点累 | 余额 ≥ 0.4G 或今天用了 60% 以上 | 减半 | 不探索 | 短一点 |
| 累 | 余额 ≥ 0.15G | 不主动 | 不探索 | 一句就够 |
| 很累 | 余额 ≥ 0.05G | 不主动 | 不探索 | 很短 |
| 空了 | 低于 0.05G | 不主动 | 不探索 | 只应一声 |

深夜（23 点到 6 点）整体降一档，早上恢复。今天已经用掉超过一整天的额度时再降一档，但不会低于“空了”。

精力只影响群聊和后台行为，不影响主人私聊：主人找她，她照常回，省的是无效判断和重复上下文，不是主人的那一间。

### 动作成本

按出厂价目表（`deepseek-flash` 峰时每百万 token：输入 2 元、缓存读 0.04 元、输出 8 元）估算：

| 动作 | 典型 token | 估算成本 |
| --- | --- | --- |
| 判断一批 | 输入 1500 / 输出 200 | 约 ¥0.005 |
| 回复一轮 | 输入 6000（七成命中缓存）/ 输出 300 | 约 ¥0.006 |
| 探索一条 | 同判断 | 约 ¥0.005 |
| 心情判断 | 输入 800 / 输出 50 | 约 ¥0.002 |
| 记忆提炼 | 输入 4000 / 输出 600 | 约 ¥0.013 |

一天 100 次判断加 20 次回复，大约 ¥0.7；主人私聊 100 轮再加约 ¥0.6。正常用不到 ¥10，真正让账本失控的是三件事：判断冷却为 0 时每批都判、回复上下文重复喂、缓存不命中。

### 省钱清单

1. **判断冷却不硬改**：出厂仍是不额外等待；精力降到“有点累”“累”“很累”时，系统分别给 15 / 30 / 60 秒的判断下限，累了就少判几次，把消息攒到下一轮。主人手动设得更大时听主人的。
2. **低信号不判**：三条以上纯表情、纯标点或反复刷同一句短话，又没叫她，直接记账不入判，零调用。
3. **缓存优先**：人设、房间规则、固定协议放在提示最前，人物卡和时间敏感内容放最后；同一间屋的判断提示保持字节稳定，缓存读比输入便宜五十倍。
4. **短应不调回复模型**：判断模型顺手给一句短反应，或走复读 / 表情。
5. **上下文按线程取**：只带与这批消息同线程的最近 6 条，不再固定 20 条；图片只在被提及时才带。
6. **判断与回复分工**：判断永远用便宜模型、低推理档；回复只在被直接叫到时继承主人的高推理档，其余用默认档。
7. **探索有预算**：精力低于“正常”就不探索；探索额度按小时封顶，不和主动额度混用。
8. **后台任务分批**：心情、提炼、章节摘要各走独立额度，不跟聊天抢；某项当天超限就顺延，不降级重试。

## 主人倾向：一句话怎么变成真行为

主人只在设置里写一段话，这段话要走完三步才算数：原文 → `compileTendency` → 一组带落点的维度。同样的文本永远编译出同样的 policy，设置页预览和运行时注入用的是同一份结果，所以“她会这样理解”可以核对。

| 维度 | 命中示例 | 落点 | 生效方式 |
| --- | --- | --- | --- |
| 话多话少 | 安静一点 / 活泼一点 | 现有旋钮 | 主动额度 ×0.6/×1.5、判断阈值 +0.06/−0.06、每批关注 ×0.75/×1.25 |
| 话长话短 | 话短一点 / 说详细 | 每轮提示 | 回复轮的分寸里加一句 |
| 玩笑多少 | 少开玩笑 / 多开玩笑 | 现有旋钮 / 每轮提示 | 少 = 幽默层整段空转；多 = 提示 |
| 发不发表情 | 少发表情 / 多发表情 | 每轮提示 | 不硬裁剪，免得把主人要她发的表情裁掉 |
| 存不存表情 | 勤保存表情包 / 别存表情 | 现有旋钮 | 自动收藏日上限 40 / 4 / 0；默认 12 |

只写提示词为什么不够，有三个原因：文字穿不过代码闸门（“勤存”仍然被日上限挡住）、长文在 12k 人设里被稀释、越长的偏好越容易被忽略。所以能落到旋钮的维度直接乘/加在现有机制上，而不是再写一段更长的提示。

优先级固定如下：

| 优先级 | 谁说了算 | 例子 |
| --- | --- | --- |
| 1 | 安全、隐私、法律、平台 / 群规、额度、权限 | 不透露主人的私事；不超额度 |
| 2 | QQ 显式硬开关 | 学表情关、试运行、静音、余额下限、总开关 |
| 3 | 主人倾向 | 安静一点、勤存表情包 |
| 4 | 出厂 / 自定义人设 | 整段 12k 人设 |
| 5 | 群语感、心情、风格贴合 | 跟着这间屋的说话习惯 |

倾向里写“活泼一点”不会把判断模型已经说的 `reply=false` 翻成 `reply`；静音、余额下限、试运行、群规和隐私也不受影响。`安静一点` 额外加一道主路径硬门槛：判断说 reply 的普通消息，把握不到阈值就只看不回；被叫、私聊、问她本人、查好感度仍然强制回。

冲突处理是确定的：同一维度后写的覆盖先写的，同一句里否定优先（“别多存”不会被“多存”抢先）。非空但一条都没识别的句子不丢，原文仍作为偏好提示注入，并标成 `unmatched`。

## 创造模式

有些倾向不可能靠旋钮或提示落地——“用颜文字”“把群友的图也收”“存完回一句”。这类请求交给本地的创造模式，让它在源码仓库里改这条鱼自己的代码，而不是假装一句话已经生效。

`GET /dsh-fish-mind/creation` 生成一份确定性 brief：主人原话、已识别落点、未识别从句、代码位置（QQ 判断 / 接话 / 表情在 `fish/plugins/dsh-qq-bridge/lib/host.js`，鱼脑在 `fish/plugins/dsh-fish-mind`）、要补的测试，以及硬约束——不动安全、隐私、法律红线、额度、权限、试运行和群规相关代码，不读写 `DSH_HOME`，不提交不推送，能做成确定性规则就别只加提示词，只影响这条鱼。

`process.cwd()` 下同时存在 `fish/bundle/package.json` 与 `fish/plugins/dsh-fish-mind/lib/index.js` 才算源码仓库；打包版只给可复制的 brief，并写明“这一版没有源码，改了也编不进去”。打开创造模式走 `workspace.startSession(undefined, { agentPreset: 'cordis', prompt, clearPreviousDraft: false })`：brief 只填进可编辑草稿，不自动发送，也不覆盖主人已有草稿。

代码改动跟着仓库和安装包走，不随记忆包；配置和倾向随「导出」走。权限层挡得住运行中的内核写入，但挡不住源码仓库编辑——这里靠明确指令加主人看 diff，不假装是沙箱。

## 可搬运的配置

导出不再只有记忆：配置按白名单写进 `manifest.configs`（`mydearfish.fish-configs` v1），zip 条目和 `ARCHIVE_VERSION` 完全不变，所以旧版本大肥鱼仍能导入新包，只是忽略配置。

| 文件 | 带走 | 永不带走 / 导入时强制 |
| --- | --- | --- |
| 鱼脑 `config.json` | 模式、注入、保留、容量、情景、召回、章节、短期、内心、幽默、话术、备份 | 零花钱额度、开发者模式、权限 |
| `tendency.json` | 全文 | — |
| 自定义人设 | 仅在主人改过时 | profile patch 的其余内容 |
| 心情 / QQ / 主动搭话 / 朗读 / B 站配置 | 偏好、模型、措辞、节奏、关键词等白名单字段 | 凭据、账号 / 群号、目标会话、NapCat 地址、本机路径、私信 UID |

导入先应用配置，再写出生设定和心情称呼，对外通道强制先关：QQ 总开关关、社交停下试运行、主动搭话关、B 站不自动评论 / 回复 / 私信。单份配置坏了只跳过并记警告，绝不阻断记忆导入；导入前把本地原文件备份到 `import-backup-<时间>/configs/`。白名单是刻意维护的：新加的秘密字段默认不进包，直到有人把它加进注册表。
