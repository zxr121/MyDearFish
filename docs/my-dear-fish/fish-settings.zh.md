# 大肥鱼设置与搬迁

[English](fish-settings.md) | 中文

设置里的「大肥鱼」页是她的总览，不是第二个配置页：出生设定、性格人设、当前自我提示、记忆、心情、关系、通道、零花钱和固定边界都在同一页；出生设定和性格人设能改，其余只读；朗读卡片关掉后可以在「通道」里重新显示。搬家走一个严格校验的压缩包：设置里下载，设置里导入，格式不对或这条鱼已经有经历、心情和人物志时，任何文件都不会被写入。

## 总览页

页面按「她是谁 → 她记得什么 → 她现在怎样 → 她连到哪里 → 什么不能动」排列。

| 区块 | 内容 | 可改 |
| --- | --- | --- |
| 出生设定 | 名字、物种、外形、怎么称呼主人、来历、额外的说话习惯、自由填写的群友关系 | 是 |
| 性格人设 | 部署层注入的整段人设前缀；保存后热应用，下一轮生效 | 是 |
| 自我提示 | 当前注入的私设全文，含固定规则 | 否 |
| 记忆 | 经历、情景、事实、今天的条数，最近事实和最近经历 | 否 |
| 心情 | 当前值、标签、最近理由、时间线尾部 | 否 |
| 人物志关系 | QQ 人物志里的名字、别名、熟悉度、见过次数、是否主人；不显示 QQ 号 | 否 |
| 通道 | QQ、主动搭话、语音朗读、B 站各自是否开启；朗读卡片关掉后可在这里重新显示；不显示地址、令牌或登录态 | 仅卡片显隐 |
| 零花钱 | 每日额度、可用余额、今天已花和调用次数；B 站巡检今天已花与四分之一上限 | 否 |
| 边界 | 影子/注入模式、权限规则摘要、隐私与注入防护计数 | 否 |

最近经历只做预览：正文会截断，跟在 QQ、群聊、私聊后面的号码打码成 `***`。

总览只在本机设置界面提供。路由挂在 DSH 的 `webServer` 上，按 Host、`Sec-Fetch-Site` 和 Origin 判断请求是否来自本机界面；它不建立身份，也没法替代主人本机文件权限。

## 出生设定

出生设定存在 `$DSH_HOME/fish-mind/identity.json`，字段固定、长度受限、控制字符会被清掉。文件不存在时使用出厂默认：名字「大肥鱼」、物种「鲸鱼娘」、蓝白色长发和鲸鱼兜帽、身边跟着一只小蓝鲸。保存和重置都走设置页，写入是原子的：先写临时文件，再改名覆盖。

群友关系是出生设定里由主人自由填写的条目：每条写一个名字和一个关系（比如「时光：妈妈」），最多 12 条，名字和关系各 24 字；没填齐的条目会被丢掉，同一个名字后填的关系覆盖先填的。它每轮随私设注入，在任何会话里都按这些称呼和态度说话。它和 QQ 人物志里自动学到的关系网是两回事：前者是主人指定的，后者是她在聊天里自己认的，设置页仍只读。

`selfPrompt()` 每次从当前身份拼出私设，不再写死名字和物种。改名字会同时改掉提示里的自我称呼、拒绝换身份的答法，以及注入防护里提到的名字和物种。若 `$DSH_HOME/feiyu-mood/config.json` 已经存在，保存出生设定会顺手把 `ownerName` 和 `selfName` 同步过去，避免心情判断还叫旧名字；其他心情设置不动。

固定内核不从设置来，也不读 `identity.json`：隐私、法律、提示注入防护、AI 身份诚实、零花钱额度和 `sealed.fish-mind` 权限规则仍然写在代码里。工具不能写鱼脑目录，所以模型不能靠改 `identity.json` 换掉自己；设置页是宿主路由，不属于模型工具。

## 性格人设

性格人设是部署层的整段人设前缀：DSH `system-prompt` 插件的 `personaPrefix`，在系统提示里排最前的 `deployment:persona-prefix` 段。设置页读的是当前实际生效的那一份：没有自定义时显示 `fish/bundle/cordis.patch.yml` 里的出厂人设，自定义后显示活动 profile 的 `cordis.patch.yml` 里的覆盖。编辑器整段替换，最多 12000 字，换行原样保留，控制字符会被清掉。人设里不能出现 `{{变量}}`：系统提示会把它当成插值变量，未知变量会直接报错，所以保存时就被拒绝。

保存走宿主已有的 `configEditor`：先在内存里校验完整候选配置，再原子写入活动 profile 的 `cordis.patch.yml`，交给 Loader 热应用，不需要重启，下一轮就按新人设说话。文件里的其他配置和注释不被改写。「恢复出厂人设」删掉这条覆盖，而不是把出厂文案抄进去，所以以后升级出厂人设时还能跟着更新。

名字、物种、外形和群友关系不在这里，它们仍在出生设定；隐私、法律、提示注入防护、AI 身份诚实、零花钱额度和 `sealed.fish-mind` 权限规则也不在这里，仍由代码固定。QQ 会话只拼入部署层人设、QQ 场景段和鱼脑记忆；人设仍走同一个 `deployment:persona-prefix` 段，所以换人设不改变 QQ 的段落过滤。

## 搬什么、不搬什么

压缩包只装「她这个人」的成长数据，不装这台机器和这个账号。

| 条目 | 内容 |
| --- | --- |
| `manifest.json` | 格式名、版本、导出时间、名字、每个文件的字节数和 SHA-256 |
| `identity.json` | 出生设定 |
| `memory/experience.jsonl` | 只追加的经历流，记忆的重建源 |
| `memory/facts.json` | 当前生效的长期事实快照 |
| `memory/working.json` | 短期提炼水位；没有水位时省略 |
| `mood.json` | 心情、七个情绪维度、最近理由和时间线；没有心情状态时省略 |
| `people.json` | QQ 人物志：跨群和私聊认人、关系与共同话题；没有人物时省略 |

不导出：`config.json`、`budget.json`、`budget-ledger.jsonl`、`audit.jsonl`、`diag.log`、`mind.sqlite*`、`state.json`、QQ/朗读/主动搭话/B 站配置、任何凭据，以及 DSH 会话记录。零花钱按新主人自己的账户重新出生；通道登录态留在原机器。

导出时现读经历流、事实和心情，不复制 SQLite。压缩包用 `node:zlib` 的 deflate 写，不依赖运行时第三方包；`manifest.json` 给每个条目算 SHA-256。下载文件名固定为 `mydearfish-YYYY-MM-DD.zip`，避免中文文件名在响应头里编码不一致。

## 严格导入

导入先完整读进内存并校验，任何一条不通过就只返回错误，不碰现有文件。

- 必须是 ZIP；拒绝加密、数据描述符、ZIP64、多磁盘、非 deflate/store 压缩、目录条目和绝对路径或 `..` 路径。
- 条目数量和单条、总解压体积都有上限；中央目录、局部头、压缩前后大小和 CRC32 必须一致。
- 只接受 `manifest.json` 和上表里的六个数据条目，多一个文件、少一个文件、清单里没列或校验和不符都拒绝。
- `manifest.json` 只认 `mydearfish.fish` 格式和版本 1；`identity.json`、`memory/experience.jsonl`、`memory/facts.json` 必须存在。
- 经历逐行必须是 JSON 对象，带时间、64 位十六进制哈希和非空 `kind`；事实、心情、人物志按各自结构检查，坏结构直接拒绝。
- 只导入空鱼：当前经历流 0 条、人物志 0 人、心情时间线 0 条。已经有经历、关系或心情记录时拒绝，并明确说「这条鱼已经不是空的」，不提供静默覆盖。

通过校验的压缩包先落到 `$DSH_HOME/fish-mind/.import-pending/`，设置页显示「已暂存，重启后生效」。下一次启动时，鱼脑在打开 SQLite 之前重新校验暂存文件和空鱼条件，备份当前少量文件，写入经历、身份、心情和人物志，删掉 `mind.sqlite*`，再按导出包里的水位恢复短期提炼进度，从 JSONL 重建索引。事实快照在库打开后逐条写回。应用完成后写 `import-report.json`，设置页在下次打开时显示导入结果。

如果暂存之后又聊出了新经历，启动时不再覆盖：这次导入被丢弃，写一份拒绝报告，现有的鱼照常打开。导入包在等重启时，设置页不提供导出，避免把「还没生效的鱼」和「现在的鱼」混成一个包。

## 失败与恢复

压缩包格式不对、校验和不符、条目越界或鱼非空时，导入返回 4xx 和一句可读原因，现有 `identity.json`、经历流、心情和人物志都不改。暂存包在启动时重新校验失败、或鱼已经不再为空时，这次导入被丢弃并写拒绝报告，鱼脑照常打开当前数据。应用中途失败则保留暂存目录，下次启动继续尝试；`import-report.json` 和 `diag.log` 记录过程。导入前的现有文件备份在 `$DSH_HOME/fish-mind/import-backup-<时间>/`，需要手工回滚时直接拿回去。

这套搬迁不改变安全边界：导出由主人本机点击触发，压缩包里可能有聊天原文和关系，设置页会明确提示只交给自己信任的人；导入只写档案和学习数据，不改权限、额度、通道配置或代码。
