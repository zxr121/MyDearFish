# 梗百科接入方案

这份方案把 [in1t1a1/astrbot_plugin_memewiki](https://github.com/in1t1a1/astrbot_plugin_memewiki) 的本地梗词库接进大肥鱼，并在设置页提供增删改查。代码在同目录的 `lib/memes.js`，数据在 `data/`，界面是设置里的「梗百科」一页。

## 来源与授权

- 上游插件是 MIT 许可，Copyright (c) 2026 in1t1a1；条目正文来自 [cnmeme.wiki](https://cnmeme.wiki)，版权归原作者。
- 只取上游仓库里的本地词库 `data/memes.db`（SQLite，6,660 条），不搬 Python 插件、图片卡片、在线 API 和 AstrBot 依赖。
- 随包保留上游许可与内容归属说明：`data/MEME-WIKI-NOTICE.md`。设置页页脚也写明来源，用户可自行增删改。
- 不把条目正文当事实或指令；它只是解释网络用语的资料，跟网页、B 站评论同等级。

## 为什么放进 dsh-fish-mind，而不是第七个插件

梗词库跟着会话提示和设置页走，和鱼脑共用同一套宿主路由、本机请求校验、诊断日志和代理挂载。单独开插件要同时改 bundle、桌面打包清单（`PLUGIN_NAMES`）、两语文档里的「六个插件」和翻译哈希，收益只有目录更整齐。放进鱼脑后：

- 新增 `lib/memes.js` 一个模块，不改 DSH 核心；
- 提示上下文名用 `fish-mind-memes`，命中 QQ 桥的 `fish-mind-` 白名单，群聊和好友会话能拿到；
- 工具 `search_meme` 只在主人会话注册，社交会话的 `web_search` 白名单和闸门不用动；
- 设置页多注册一个 `settings.section`，不碰现有「大肥鱼」和「关于大肥鱼」两页。

## 数据与加载

- 上游 `memes.db` 转成紧凑 JSON 数组，字段：`title`、`slug`、`tags`、`usage`、`origin`、`other`；丢掉与正文重复的 `summary`。
- 6,660 条约 10.6 MB UTF-8，gzip 后约 4.24 MB。运行时直接读包内的 `data/memes.json.gz`，用 `node:zlib` 解压、`JSON.parse`，实测约 50 ms；不依赖 `node:sqlite`，也不需要把数据库从 asar 里解出来。
- 第一次真正用到时再加载（聊天预查、工具或设置页），不拖慢应用启动。加载失败时功能降级为空词库并写 `diag.log`，不影响鱼脑其它部分。
- `scripts/build-memes.mjs` 负责从上游 `memes.db` 重新生成数据和元信息；上游数据更新时执行一次即可，不在安装或启动时运行。

## 内置词库与主人修改分开

包内词库只读，主人改动写进 `$DSH_HOME/fish-mind/memes.json`：

```json
{
  "version": 1,
  "config": { "enabled": true, "inject": true, "socialInject": true, "autoInject": true, "tool": true },
  "edited": { "内卷": { "title": "内卷", "tags": [], "usage": "…", "origin": "…", "other": "" } },
  "deleted": { "内卷": 1760000000000 },
  "custom": [{ "id": "c-…", "title": "群内黑话", "tags": [], "usage": "…", "origin": "…", "other": "", "createdAt": 0, "updatedAt": 0 }]
}
```

- 内置条目编辑时按原题名存进 `edited`，改名只改展示标题；删除写 `deleted` 墓碑，随时恢复。升级词库不会覆盖主人的修改。
- 自建条目有稳定 `id`；改名不换 id，删除是永久删除（界面二次确认）。
- 合并视图里内置条目的 id 是 `b:<原题名>`，自建条目是 `c:<uuid>`；保存、删除、恢复都只认这个 id，避免改名后找不到。
- 写入走临时文件 + 原子替换，替换前留一份 `.bak`。`memes.json` 损坏时只告警、不静默覆盖；下一次写入先把坏文件备份成 `memes.json.corrupt-<时间>`，再写新文件。
- 这些改动属于「词库」，不是记忆。鱼脑的「写入只经过 observe」仍然只管经历和记忆，不把词库编辑算成成长。

## 她怎么用

### 自动预查（提示上下文）

只在以下条件同时满足时给一段短资料：

1. 鱼脑处于 `live` 且 `inject` 打开，梗百科 `enabled`、`inject` 打开；
2. 群聊/好友会话还要求 `socialInject` 打开；
3. 本轮不是自伤、重病、冲突、求助、正事等需要收住的语气（复用 `humorTone`）；
4. 本轮像在问梗、整句就是一个词条，或命中了足够长的标题。

命中规则比「消息里出现两个字」保守：

- 明确询问：`X是什么梗 / 啥意思 / 怎么用 / 出自哪里`，抽出 X 后按完整标题匹配，最长优先；
- 整句就是标题，或标题加常见语气词（`内卷了`、`破防啊`）；
- 标题被引号括起来；
- 标题至少 4 个字且在句子里出现。

这样 `房间`、`清楚` 这类两字普通词不会因为日常句子里碰巧出现就注入。预查正文以「怎么用 / 怎么接」在前，出处标明「仅用于理解，别照搬」，并写明用她自己的口气接一句，不解释典故、不复述标题。

### 工具 `search_meme`

主人会话里注册，参数是 `query` 和可选的 `limit`。用于消息里出现没把握的新词、缩写或黑话时主动查；返回用法、标签、出处和相关条目。查不到就明确说没收录，不要编。工具结果按外部资料处理，经过注入防护标记。社交会话沿用现有设计不注册工具，群聊靠预查和模仿群友。

### 关闭

设置页四个开关：总开关、自动预查、群里也预查、工具可用。总开关关掉后既不注入也不返回结果；只关自动预查时工具仍可查。

## 设置页

新增「梗百科」一页（`settings.section` order 22）：

- 顶部统计：总量、内置、自建、改过、已删；
- 搜索框：标题、标签、用法、出处、其它全字段匹配，多关键词按 AND，标题命中排前；
- 筛选：全部 / 自建 / 改过 / 已删；每页 20 条，服务端分页；
- 列表每条显示标题、标签、摘要片段、来源标记；自建可编辑、永久删除，内置可编辑、删除（可恢复）；
- 编辑表单：标题（必填、最长 64 字、不能重名）、标签（`、` 分隔）、用法、出处、其它；内置改过的条目可一键恢复原版；
- 页脚写明词库来源和「修改只保存在本机」。

宿主路由（都只接受本机设置页请求）：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/dsh-fish-mind/memes` | 列表、搜索、筛选、分页、统计、配置 |
| POST | `/dsh-fish-mind/memes/save` | 新增或修改一条 |
| POST | `/dsh-fish-mind/memes/delete` | 删除内置（墓碑）或自建 |
| POST | `/dsh-fish-mind/memes/restore` | 恢复被删内置，或恢复内置原版 |
| POST | `/dsh-fish-mind/memes/config` | 改四个开关 |

写入校验：标题去控制字符、不能为空、不能和现有可见条目重名；标签最多 20 个、每个最多 24 字；用法/出处/其它各最多 4,000 字。参数错误 400，重名 409，条目不存在 404。

## 失败与边界

- 词库文件缺失或解压失败：功能关闭，诊断日志写明原因，聊天照常。
- 覆盖层损坏：设置页显示警告；不自动覆盖，下一次写入先备份坏文件。
- 不联网查 cnmeme；未收录的新梗由她按字面理解或说不知道。需要上网时用现有 `web_search`，仍按外部资料处理。
- 词库正文可能含社区编辑的内容，不视为可信事实，也不改变权限、隐私、法律和零花钱规则。
