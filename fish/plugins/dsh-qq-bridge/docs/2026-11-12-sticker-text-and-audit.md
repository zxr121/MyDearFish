# 表情备注只写画面、不读图上的字（2026-11-12）

## 结论

不是识图模型看不见字，是提示词让它别看。`看图起名系统` 只要求 2–12 字的画面名，
还写着“只是文字排版就整行输出「无」”。模型照着做，于是带字的梗图只落成
「粉发紫眼坏笑脸」，图上的“我一鸡巴插死你”一个字没进备注，自动收藏也没有任何内容门槛。
QQ 收藏里的备注和她的盲挑清单都拿这个画面名当唯一依据，她既不知道这张图在说什么，
也不会因为字脏而避开。

## 记录里的两幕

- 11-11 14:25：主人说「我看了下它存这个表情包只备注了图的特征，却没注意到除了图还有文字」。
- 11-12 10:03：主人判定「别的看不懂就算了，这次字都不认识」「感觉这个需要紧急修理了」。
- 11-11 10:17 主人已经手动清理过一次表情包池；截图里的 #188 就是漏网的一张。

## 做法

### 1. 看图从“起名”改成“登记”

一次调用输出三行：

```text
样子：粉发紫眼坏笑
文字：我一鸡巴插死你
可存：色情
```

- `样子` 沿用原来的 2–12 字画面名规则。
- `文字` 要求按原顺序原样抄，不翻译、不概括、不打码、不美化；没有字写「无」；最多 30 字。
- `可存` 只认「可以」或一个类别：脏话 / 色情 / 暴力 / 恐怖 / 歧视 / 广告 / 政治 / 隐私 / 恶心 / 其他不适。
  判不准就按字面判，字面已经骂人、性、暴力就不能写「可以」。

解析不依赖模型完全守格式：三行拆不出来时，只把第一行当画面名，`完整: false`，
这种结果不能用来放行自动收藏。

### 2. 备注必须带图上的字

`拼表情名(画面, 文字)` 输出 `画面「图上的字」`，总长不超过 24 字；字太长留前半句加省略号。
没有字就只写画面名。看图拼出来的名字走 `改收藏表情备注(..., { 原文: true })`，
不会被聊天备注清洗把「」剥掉。

### 3. 存之前过内容门槛

- 自动收藏和她自己写的 `[存表情]`：必须拿到完整的 `可存` 判定；脏话、色情、暴力等不落地。
  没配能看图的模型、超时、模型没按格式回答，也先不自动收。
- 模型判「可以」时，本地再用明确的性词 / 强脏话过一遍；普通的“打死你呀”这种玩笑不拦。
- 主人明确让存：照存，但标 `慎用`，并回一句说明；受信人让存的不雅图仍不收。
- `不存表情` 关键词也会匹配画面名和图上的字。
- 商城官方表情自带官方名，自动收藏不额外读图；之后被再次遇到时会补读一次。

### 4. 慎用

`慎用` 的表情保留在 QQ 收藏和本机索引里（SnowLuma 没有删除收藏表情的接口），
但不进回复 / 判断清单、不参与盲挑，编号仍能被主人点名。想彻底删掉要去 QQ 收藏里手动删；
她那边的发送失败路径会在 QQ 里找不到这张时自动从本机清单删掉。

### 5. 旧收藏自查

`POST /dsh-qq-bridge/stickers/audit`（可带 `{ ids }`，`{ 停: true }` 停下）在后台逐张取原图重读：

- 记 `看图文字`、`查过At`；
- 图上的字没进备注时补进去；
- 不雅内容标 `慎用`。

设置页「收藏里的图上的字」按钮触发同一个流程，进度在 `/state` 的 `表情包.普查` 里轮询，
并列出慎用清单。查过的不会重查；读不出来的不记 `查过At`，下次可以再查。
主人看过清单后觉得某张其实没问题，可以点「恢复」（`POST /stickers/use`，带 `{ id }`），清掉慎用标记；
觉得该删就点「删除」（`POST /stickers/delete`，带 `{ id }`）：先删 QQ 收藏，成功后再删本机条目，并把 md5 记进
`qq-stickers.json` 的 `deleted`，自动收藏以后不再收回同一张。

## 不做

- 不把脏话写进被拦下的自动收藏备注：直接不收，避免 QQ 收藏里多一条自己都不想看的记录。
- 不删 QQ 收藏里的表情：没有接口，也不替主人动账号数据；只保证她不再主动发。
- 不因为“模型判可以”就放行：本地兜底是第二道闸。

## 验证

- 纯函数：三行解析、图上文字清洗、名字拼装、本地脏话兜底、内容判定。
- 自动收藏：脏话图两张也不收；普通带字图收下并写 `猫猫举牌「今天也要开心」`。
- 普查：指定编号重读，模型判「可以」但字里有脏话，仍标慎用、把字补进备注并同步 QQ；
  查过记时间；慎用不进可发清单和回复提示。
- 既有流程：按图重看、主人让存、[存表情]、[发表情:图N] 先存再发、商城表情、宿主半边全部回归。
