# 人写过的表情备注不再被系统改掉（2026-11-13）

## 结论

根因在 `泛标签()`：它把 11 个场合名（打招呼、道别、笑、赞同、无语、惊讶、生气、安慰、可爱、感谢、接话）
也当成“没起过名”。按图重看、「查一遍收藏」以及再次见到同一张时的自动改名只看这个判断，
于是主人手写的「笑」「无语」「可爱」会被系统按新画面改成别的名字。

修法不是再加一个“场合名黑名单”，而是记住**名字是谁起的**：条目新增 `labelBy`，
自动改名只碰 `auto` / `sync` 的占位名。

## 字段

`qq-stickers.json` 的条目新增 `labelBy`：

| 值 | 谁写的 | 自动改名的对象 |
| --- | --- | --- |
| `owner` | 主人（主人要求存图 / 改备注 / 主人桥） | 不动 |
| `friend` | 受信的人或群友 / 好友给的短名字 | 不动 |
| `auto` | 按图起名、商城官方名、自动收藏 | 可改 |
| `sync` | 从 QQ 收藏同步来的占位名 | 可改 |

写入口：`存表情包()` 建条目时按 `选项.名源` / 来源落值；`改收藏表情备注()` 用 `选项.名源`
在改名成功时一起写，QQ 备注失败时和 `label` 一起回滚；QQ 同步把远端真名字按 `owner` 收下，
占位名按 `sync` 记。

## 改名闸门

- `是占位表情名()`：空名、`表情` / `未命名` / `图片` / `主人让存` / `受信让存N` 这类兜底名。
  场合名**不**在其中。
- `表情名源()`：优先用 `labelBy`；老索引没有字段时按名字推断——兜底名算 `auto`，其余算 `legacy`（按人写的处理）。
- `可自动改表情名()`：`auto` / `sync` 才能自动改，`legacy` 不动。
- `该重看表情备注()`：`可自动改表情名() && 是占位表情名(label)`。
  「查一遍收藏」和默认的 `stickers/relabel` 都用它挑候选；人写的名字不在这批里。

显式带 `ids` 调 `POST /dsh-qq-bridge/stickers/relabel` 仍会强制按图重起，
这是主人点名维护的动作，不按自动改名处理。

## 老数据

不迁移、不改写旧索引：老条目的 `labelBy` 留空，运行时推断。
旧收藏里的「笑」这类真名字按 `legacy` 保护；「表情」「未命名」仍可被按图补名。

## 验收

- `node tests/宿主半边.mjs`：占位名 / 起名来源 / 可自动改名 / 该重看四个纯函数用例；
  主人改名、主人要求存图落 `labelBy: owner`；自动收藏落 `auto`；商城官方名落 `auto`。
- `node tests/社交半边.mjs`：QQ 同步来的「手动加的海獭」被普查重读后名字不变；
  系统起的「青蛙举牌」仍能把图上的字补进备注（`青蛙举牌「开饭」`）。
