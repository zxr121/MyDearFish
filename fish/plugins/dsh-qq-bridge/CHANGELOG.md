# 改动记录

> **版本号规矩**：每改一次 **+0.0.1**；末位满 10 **进位**（`0.1.9` → `0.2.0`）。
> 版本号只写一处真源：`package.json`；提交信息也以版本号开头。

## 0.2.0

**兴趣快判：学习期每条都判，画像成熟后先做零成本粗筛**

- ✨ 每个群 / 好友从她真正看过的群友消息里积累兴趣画像（中文双字 + 拉丁词；
  主人、被叫但没看、被快判挡掉的消息都不算）。
- ✨ 画像成熟（看过 20 条、攒出 6 个稳定词）后启用快判：明显无关的群友消息不再进入判断窗口；
  整批都没兴趣时一次判断模型都不问；被叫和主人的消息永远进慢判。
  快判只决定要不要花判断钱，不替她决定看不看、回不回。
- ✨ 新增 `快判` 开关（默认开）；`/state` 每个目标多出 `画像`（样本、稳定词、是否成熟、挡掉条数、跳过批数）。
- ⚙️ 设置页显示「快判学习中 N/20」或「快判已成熟（挡了 N 条）」。
- 📄 兴趣依据参考人类注意与兴趣研究：价值驱动的注意捕获、MODE 模型、预测误差门控、专长组块化。

## 0.1.9

**社交模式：她自己挑看什么、自己决定回不回，被 @ 不再必回**

- ✨ 注意力改为兴趣驱动：只挑她真正感兴趣的内容看，也只因为感兴趣才可能接；
  能回答、被 @、群里热闹都不算理由；判断的 `reason` 必须写出具体兴趣点，写不出就不看或不接。
- ✨ 判断模型升级为「注意力 + 接话」两级判断：先从新消息里挑出要看的 `watch`，
  再给出要不要接和把握；没挑中的消息她当没看见，不会进入社交会话。
- ✨ 被 @、被叫名字、被回复只是「可能在叫她」的标记，不再自动回；好友私聊也先由她判断。
- ✨ 新增 `关注上限`（默认 12，范围 1–30），限制一次判断最多把几条消息放进她的视线。
- ✨ 只看不回改为 `agent.inject`：挑中但不接的消息记进上下文，不唤醒回复模型，只花判断的钱。
- ✨ 待看队列：判断冷却期间新消息保留到下一次一起判；硬闸拦住时清空并节流记日志；
  队列上限 50 条 / 12000 字，新的优先；刷屏时被叫和主人的消息优先保留，不会被挤出待看或判断窗口。
- ✨ 回复冷却只拦开口，不拦看：冷却中仍可只看不回。
- ⚙️ 移除 `被叫直接回`；旧配置字段会被忽略并在 `/save` 时清掉；`/state` 增加每个目标的 `待看`。
- 📄 设置页与 README 同步改成「她自己挑、自己决定回不回」的说法。

## 0.1.8

**社交模式：她在群里自己判断接不接，先过成本闸门**

- ✨ 每个群 / 好友开一间独立会话（`session-qq-social-group-*` / `session-qq-social-friend-*`），
  上下文连续，但不混进主人平时那间屋子。
- ✨ 被 @ / 叫到名字 / 回复她的消息 → 直接回；没被叫 → 便宜的小模型判断要不要接，`[不接话]` 就不发。
- ✨ 成本闸门：静音、冷却、单目标小时/日上限、全局日上限、鱼脑零花钱下限；判断也有独立冷却，
  判断和回复都走鱼脑账本。建议先开「社交试运行」，只记账不花钱。
- 🔒 社交会话没有工具、不注入余额；记忆只查这一间会话（精确会话 id，群号前缀相同也不会串）；
  群友内容按不可信资料处理；对外发送失败关闭。
- 🔒 主人的群消息仍走原来的目标会话，不在社交桥重复回；她自己的发言靠 `get_login_info` 过滤。
- ⚙️ 设置页新增社交卡片：群/好友清单、模式、被叫直接回、旁听、限额、静音、称呼/兴趣词、
  判断/回复模型、判断冷却与阈值，以及每个目标的实时状态。
- ⚙️ 新增 `GET /dsh-qq-bridge/models`；`/state` 增加 `社交` 状态；`/save` 对 `社交` 做深层合并。

## 0.1.4

**`QQ → DSH` 这半彻底搬进插件，不再赖 BOT**

- 插件每 4 秒轮询 NapCat 的 HTTP 历史接口（`get_friend_msg_history` / `get_group_msg_history`），
  发现她新发的私聊/群消息 → 直接 `followup` 进目标会话。
- 只认 `私聊QQ` 这个人发的；自己的回话（self 消息）不会自我繁殖成死循环。
- 靠 `message_id` + 时间戳去重，同一条不重复转；总开关关 / 没选会话时只推进时间、不处理旧消息。
- 结论：**这台桌面只要 NapCat + 这个插件，BOT 可以完全不要了。**

## 0.1.3

**QQ→DSH 这半的 BOT 半场也接上了**（改在 Estrella 那边，不在本仓库）

- Estrella（BOT）加了 `custom.qqBridge` 开关（**默认关**）：打开后，私聊/群里**她本人**说的话
  由 BOT 转发到本插件的 `/receive`，然后 BOT **闭嘴不回**，全交给 DSH 的大肥鱼。
- 兜底：转成功 → BOT 不回；转失败（DSH 没开 / 连不上）→ BOT **照常回**（桥断 ≠ 鱼哑）。
- 本仓库只是把这件事写进 README（见「怎么把 BOT 接上」）；运行入口仍是 0.1.2 的 `/receive`。

## 0.1.2

**加了「QQ → DSH」这半的入口**（`/receive` 路由）

- BOT 把她说的话 POST 到 `/dsh-qq-bridge/receive`，这里用 `agent.followup(手搓 user 消息)` 走 DSH 自己的回合。
- 消息 `source.kind = 'qq'`（不冒充她亲手在 DSH 里打的）。
- 闸门：没选目标会话 / 总开关关 / 会话没活着 / 空 text 都拒绝，并回一句人话。
- BOT 那边（Estrella 改动）要在这半之后再接上。
