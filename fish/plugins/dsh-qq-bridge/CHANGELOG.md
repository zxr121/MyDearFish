# 改动记录

> **版本号规矩**：每改一次 **+0.0.1**；末位满 10 **进位**（`0.1.9` → `0.2.0`）。
> 版本号只写一处真源：`package.json`；提交信息也以版本号开头。

## 0.2.11

**@ 只是提醒注意，不保证回复**

- ✨ 群聊里 @ / 叫名字不再绕过兴趣判断，也没有任何“直通”开关；被叫只让她优先注意到这条，
  是否回复仍然看兴趣和把握。
- ✨ 图片也不特殊：和文字一样走同一套判断；被选中后才下载 / 作为 image 块进会话。
- 🔧 移除 0.2.9 的「群聊 @ 也直接接」开关；旧配置里的值会被忽略。
- 💬 私聊仍保留主人 / 好友区分：主人的私聊走 QQ 私聊专用屋，好友才走社交判断。

## 0.2.10

**群聊不再分主人 / 群友**

- ✨ 群聊路由统一：任何人 @ / 叫名字（开关开着）或发图都直接开一轮；其他消息都走同一套兴趣判断。
- ✨ 主人在群里不再自动被挑中、不再优先保留、不再“只当上下文”；刷屏保留、快判、兴趣画像、
  判断提示全部按同一标准处理所有人。
- ⚙️ 主人桥正在转发这个群时，主人的消息走主人桥，不再进社交房，避免重复回。
- 💬 私聊仍保留主人 / 好友的区分：主人的私聊走 QQ 私聊专用屋，好友才走社交判断。
- 🧪 测试改成“主人没叫也走判断、主人 @ 和群友 @ 走同一条直通路”。

## 0.2.9

**群友 @ 可直通；判断失败不丢消息**

- ✨ 新增「群友 @ 也直接接」（默认关）：打开后群友 @ / 叫名字会直接开一轮，她仍然可以选择 `[不接话]`。
- 🐛 判断模型回了坏 JSON / 调用失败时，不再把整批消息静默丢掉；留在待看队列，冷却后重判。
- 🔧 判断输出上限 240 → 512，减少截断导致的「判断结果看不懂」。
- 🧪 补了群友 @ 直通、判断失败留存的测试；设置页新增开关。

- ✨ 上下文里的旧图不重复占图片位，新图优先；回复时不会因为旧图太多把新图挤掉。
- 🧪 补了“下一轮回复能接上上一句”的测试。

## 0.2.2

**翻旧记录对上 Tulpa 0.5.x 的真接口（offset 翻页 + 快照冻结）**

- 🔧 历史工具改按参数表挑：会话参数、翻页参数、方向参数都算分，`since` / `after` 这类增量工具和
  `query` 这类搜索工具减分。此前按名字挑会选中 `get_messages_since`，整段历史只能读到最新一页；
  现在选中 `read_conversation`（参数表里没有会话、翻页证据的一律不选）。
- 🔧 认 Tulpa 的 offset 翻页：游标存 `next_offset`，翻完 `has_more=false` 就收；会话目录自己分页
  （每页 20 间）也翻完为止。带时间游标的老服务照旧走时间翻页那条路。
- 🔧 每间屋第一次翻到就把 `snapshot_max_id` 冻进游标，续翻原样带上：导到一半新消息入库也不会挪页界。
- 🔧 Tulpa 的文本时刻（`2026-10-21 08:04:35 +08:00`）如实解析成毫秒；不带时区按北京时间算，认不出按跳过。
- 🔧 整条只剩占位（`[动画表情]`、`[图片] [语音]`）的消息跳过不写：没有可记的内容，不编。
- 🔒 聊天记录里夹带的令牌（`sk-`、`ghp_`、`github_pat_`、`xox`、`AIza` 一类样式）落库前换成 `[机密]`：
  事情记得住，原文留不下；整条密钥消息变成一条 `[机密]` 事件，时间和说话人照旧。
- 🐛 一页中间停到 `每轮条数` 上限时，游标留在这页开头：下轮重读这页，写过的靠哈希算重复，
  不再把后半页悄悄漏掉。

## 0.1.4

**`QQ → DSH` 这半彻底搬进插件，不再赖 BOT**

- 插件每 4 秒轮询 NapCat 的 HTTP 历史接口（`get_friend_msg_history` / `get_group_msg_history`），
  发现她新发的私聊/群消息 → 直接 `followup` 进目标会话。

- 靠 `message_id` + 时间戳去重，同一条不重复转；总开关关 / 没选会话时只推进时间、不处理旧消息。
- 结论：**这台桌面只要 NapCat + 这个插件，BOT 可以完全不要了。**

## 0.1.3
