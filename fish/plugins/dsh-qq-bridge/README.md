# 通到 QQ（dsh-qq-bridge）

让 DSH 里的 **AI 伙伴**和 QQ 连起来：它在 DSH 里说完话，自动发到 QQ。

> 现在两半都做出来了，而且**都不用 BOT**：
> - `DSH → QQ`：伙伴说话 → 发到 QQ。
> - `QQ → DSH`：你在 QQ 里发话，插件自己轮询那个 QQ 后端收进来 → 转进 DSH。只要一个后端就够。
> - **社交模式**：她还能在指定的群 / 好友里**按兴趣主动开话题、自己决定要不要接话**；不感兴趣也能短接一句，不会被兴趣挡在门外。
> - **翻旧记录**：把 Tulpa 里已经存在的私聊历史**只读**导进鱼脑的经历流，让她真有一段过去可回忆（只写记忆，绝不说话）。
> - **收得到戳一戳**：QQ 的戳一戳不在聊天记录里；插件在本机开一个收报口，让 SnowLuma 把事件推过来，她就知道被戳了。
> - **看得懂合并转发**：群里的“转发消息 / 聊天记录”会向 QQ 后端展开，按「说话人：内容」一行一条带进上下文；转发里的图片也会下载下来一起看。
> - **看得懂引用**：别人引用哪条消息，插件会回查原消息，把「[引用谁：原话]」放在正文前带进上下文；引用她自己说的会标成「[引用你：原话]」，就算消息 id 已经不在内存里，也认得出是在跟她说话。
> - **回话会引用**：她写 `[引用:那句原话]` 就能挂上 QQ 原生引用，别人在 QQ 里能看到她接的是哪一句；标记自己不会发出去。

**第一次用？** 打开 **DSH → 设置 → 通到 QQ**，照着最上面的「第一次接通 QQ」三步走：
一键安装 SnowLuma（本机已有的会自动认出来，不重复下载）→ 登录鱼 QQ 并在 SnowLuma 后台接上 → 回来检测。
连上之后在「她在哪里说话」里**只填一个号**：群号 = 她在群里听和接话，QQ 号 = 和你私聊；是群还是好友按鱼 QQ 自己的名单自动认，不用再填类型、端口或会话。

## 现在的行为

- 盯一个「目标会话」——**留空就行**：第一次私聊时会自动开一间 `QQ 私聊 <你的QQ号>` 的专用屋，之后一直续上；也可以手选你平时和它聊天的那一间固定住。
- 自动开的会话会挂到现有工作区；一个工作区都没有时，会在当前目录建一间，不用你先手动准备。
- **图片能看**：QQ 里的图片会从 QQ 图片域名下载、校验后存进 DSH 附件库，作为 `image` 块交给模型；
  主人私聊 / 群聊、好友私聊都生效。图片和文字走同一套规则，不会单独触发回复；被叫 / 兴趣判断选中后才进会话。
  单条最多 4 张、每轮最多 6 张，只收 png/jpeg/webp/gif；坏图、超限、超时只跳过图片，文字照常进会话。
  判断模型本身能看图时，这一批最多 2 张新图也会随判断请求递过去，她按图里的内容决定接不接；
  回复和判断模型都要选支持图片输入的（如 `deepseek-flash`），设置页会标出「仅文本」并在状态里写明能不能看图。
  这一轮的话在说“图 / 照片 / 像不像 / 这是你吗”时，最近聊过的旧图也会重新附上一次（先挑这轮说话人之外的人发过的，最多 2 张）：
  旧图标成 `[旧图 N]`、注明是谁之前发的，跟这轮新图的 `[图 N]` 分开，免得她拿这轮新图硬套；没说图就不重复附，省图钱。
  有人问“这张像不像你 / 这是不是你”时，先直接答像或不像、再最多补一句，不逐项念图里的颜色和衣服；
  别人随手发的图 / 表情，她接的是这张图的意思：看懂就说中（“这是哈气吧”“凶巴巴的”），拿不准就短问，
  不报发色、配色、耳朵、眼睛这些画面细节，也不替静图编“喊破嗓子 / 急出来的”这类动作；
  对方明确问颜色、人数、写的什么字这些细节时照答，不绕开；
  认错图就照对方指的那张重答，拿不准是哪张就问，不自己换一张接着猜。
- **会用 QQ 收藏表情**：看到别人发的 QQ 表情类图片，她觉得有意思会自己收藏（自己随手收的只收“动画表情”）；
  主人明确让她存哪张时，普通照片也照存。收藏直接写进这个 QQ 号的「收藏表情」，聊天时用 `send_custom_face` 从那里挑一张发出去，保留 QQ 的表情样式。
  **QQ 里手动加的表情也会自动记住**：连上后端后每 5 分钟对着账号里的收藏清单核一次（只读，不改收藏），
  按表情编号和图片 md5 认回已有的、补上后来改的备注；手动加的直接进清单，备注空的先叫「未命名」。
  收藏超过 200 张时先让位给 QQ 里已经删掉的旧条目，还在收藏里的不动。
  回复提示会列出全部收藏（同名合在一起写编号）；收藏里有「未命名」的会多提一句：只有编号、看不出内容，别猜着发，只在图注标出编号或主人点到时才用。
  本机 `.dsh/qq-stickers.json` 只留编号、备注和资源 ID，不存图片文件；最多 200 张，设置页显示数量和最近几张。
- **自己攒表情包**（「学表情」默认开）：她一边看群一边记群里怎么用表情——多少条消息里带表情、
  是不是经常只发图不配字、一轮连发几张、常用在什么场合（笑、赞同、打招呼、无语、安慰、感谢等）。
  只存统计，不存原话、不存图。同一张表情在半小时内又见到（群和好友私聊都算）、或这个群常在某个场合配表情时，
  她会把那张表情类图片顺手收进 QQ 收藏，备注用场景名（如“笑”）；场景统计只看群，私聊里只按「又见到同一张」收。
  只收表情类，不收主人发的图，每天最多自动收 12 张（「性格倾向」里写「勤存」40 /「少存」4 /「别存」0，见下文），试运行不写。收藏快满（200 张）时不再收；她之后真起了短名字，会覆盖场景名。
  攒够样本后，回复提示里会带一句「这个群的表情多用在：…」，并且允许她**只回一张表情、不配文字**。
  设置页「学表情」关掉 = 不统计、不自动收藏，也不在回复提示里提群体表情习惯。
  旧版存在 `.dsh/qq-stickers` 的图片会在连上后端后自动迁进 QQ 收藏，成功就删掉本地图片；社交试运行时不写收藏。
  主人明确说“收藏下表情包 / 你保存下这几个”时（有 @、叫名字或话里带着“你”都算），即使她这轮只看不回，
  也会把这一批里主人和群友刚发的图直接存进 QQ 收藏；主人先说了存、图下一批才到时，会记 5 分钟等图来了补存。
  同一张表情再发一次时，她按图片内容（md5）认出这是收藏里的哪一张，消息行会标「你收藏的 #N 名字」；
  提示里直接写「图 N 就是你收藏的 #N」并给出可发编号：两张不同的表情不会被说成同一张，没收藏过的也不会说成收藏过。
  私聊 / 主人桥也走同一套：主人说“这个存下来 / 收藏一下”时，这一批里他发的表情当场写进 QQ 收藏；
  要“把这张发回来”时她写 `[发表情:图N]`（这一批的第 N 张），没收过会先存再发，发出去的就是这一张；
  她起的短名字（`[存表情:图N:短名字]`）会覆盖自动收藏的“主人让存”，并同步回 QQ 收藏备注；存失败会标“没存成”，不会假装存好。
  这一轮没真存成、她的话里却写了“存好了 / 存着了”时，发出去之前会改成“我试了，没存进去”（没动手时改成“我看看能不能存”）。
  收藏是她自己的小动作：群里存了不汇报，被问起再照实认，清单里没有的不会顺口说存过。
- `DSH → QQ`：它在某**一整轮的最后一句**说完，先把文字过一遍鱼脑的 `redactOutbound`，再把脱敏后的版本发到 QQ（走配置里的 OneBot 地址）。
- **能连发**：回复里的空行是分段信号——空行隔开的每段作为一条消息单独发出（段间停 0.4~1.2 秒，
  按上一条的长短和一点随机抖一下，一次最多 3 条），像真人连着发几条气泡；没有空行时单换行也按分条算，
  整段多句还会按句尾自动断条。超限的段落并进最后一条，不会悄悄丢字。
  省略号、`？！` 这类连着的标点算一处句尾，不会从中间断开；整条只有标点（单独一行 `……`）的段不单独发一条，
  并进相邻那条，前一条已经以省略号收尾时不再叠一层。
- **表情包也能连发**：`[发表情:#N]` 写几张就发几张（一次最多 24 张），和话混着写时按写下顺序一张张、一句句发出；
  写成 `[发表表情#N]`、全角括号 / 冒号、漏冒号或带空格也按那张表情发；只写 `[#N]` 的短写同样认。
  编号不会当正文发出去：括号里认不出编号的整条删掉，被截断的半个 `[#N`、`[发表情:#` 也不发。
  只写一张表情、不配任何文字也是一条完整回复；被叫到、好友私聊时，只回一张表情也算接上了。
  判断模型的档位 1 短应也能只挑一张收藏表情（不配字、不叫回复模型），节奏和退路见下文「短应也可以只是一张表情」。
  提示里会建议她别每句都发、一轮最多两张，什么时候发由她自己看着办。
  收藏里没有的编号只跳过那张，不挡后面的内容，并在她下一轮消息里标一句「表情没发成」，免得她以为发出去了。
  `[存表情:…]` 是收藏指令，不算发送内容。
- 脱敏服务不可用、报错或脱敏后为空时，这一条不发，不会退回原文。
- `QQ → DSH`：插件每 4 秒轮询 QQ 后端（`get_friend_msg_history` / `get_group_msg_history`），
  发现你在 QQ 里新发的消息 → 转进目标会话，让它照常开一轮。
- 同一次轮询里收到的好几条消息会**合并成一轮**转进去，不会一口气开好几轮；
  单条上限 8000 字、一次轮询合计 12000 字，超出部分标明「后面省略」。
- **她也会自己起话头**：装了 `dsh-speak-up` 时，它通过本插件暴露的 `qqSocial` 服务拿 QQ 群 / 好友清单
  （默认全部勾上），掷中了就自己开话题。送之前桥先把关：总开关 / 社交开关、这间的单独开关、只听、歇着、
  试运行、静音时段、主动话量——任何一条不满足就只记账、不真发；能开口的 QQ 房间平时没开着也没关系，
  桥会按需把它开出来。真发出去的主动话头算**主动话量**（跟接话共用每时 / 每日额度）。
- **卡住了会说，坏掉了能换**：社交群 / 好友连续 3 轮没完成（回合以错误结束，或等满 180 秒），
  这一路先停 10 分钟、不再开新回合；主人私聊连续 3 轮报错时不停，但会一起提醒。
  两种情况都会给主人 QQ 发一条 `【大肥鱼·系统】`（同一条路线每小时最多一条；试运行和静音时不打扰）。
  设置 → 通到 QQ 里能看到连续失败次数、错误码和暂停截止时间，旁边有「重置这个聊天」：
  点一下换一间新会话（id 形如 `<旧id>-r<时间>`），**旧聊天原样留在磁盘上，不删**，之后的消息直接进新屋。
  重置记录存在 `.dsh/qq-bridge-sessions.json`，重启后仍然生效。
- **合并转发能看**：QQ 里的“转发消息 / 聊天记录”在历史接口里只有一个 `forward` 段和 id，
  插件会调后端的 `get_forward_msg` 把它展开，按 `[转发消息 N 条]` + 「说话人：内容」一行一条放进上下文；
  主人私聊 / 群聊和社交会话都生效。大转发只展开前 20 条、每条最多 160 字、总计 1200 字；
  转发里的图片会一并下载进附件库（最多 4 张，图注写明原发言人；坏图 / 超限跳过，不影响文字），
  转发里的转发只留 `[转发消息]` 标记；后端没开这个接口或超时，外面那句话照常进上下文，只在原处留 `[转发消息，没展开出来]`。
- **引用能看**：QQ 的引用在历史里只有一个 `reply` 段和消息 id。插件会调后端的 `get_msg` 回查被引用的消息，
  把 `[引用谁：原话]` 放在正文前一起进判断和会话；被引用的是她自己发的消息时标成 `[引用你：原话]`，
  并直接算作“在回复她”，不再依赖内存里的消息 id。原消息太长只带前 160 字；同一条引用缓存复用；
  消息太旧、后端不支持或超时，只跳过引用原文，正文照常收。主人桥转发的消息按发送人名字标，不会把主人自己的话写成她说的。
- **回话会引用**：有人回复她时，回话的第一条文字挂上 QQ 原生 `reply` 段，引用的是**对方回她的那条消息本身**，
  不是那条消息引用的旧话；被 @ / 叫名字，或她自己想接一句时不自动挂引用。
  她想主动接住哪一句，就写 `[引用:那句原话]`（编号是负数也认 `[引用:#编号]`），插件会在这间屋最近的消息里对上
  那一条，把引用挂到第一条文字上。原话对不上就只发正文，绝不退回去挂别的消息；标记本身绝不会发进聊天。连发多条时只有第一条带引用。
- **戳一戳**：QQ 的戳一戳是 OneBot 的 `notice/notify/poke` 事件，不在 `get_*_msg_history` 里，
  光轮询永远看不到。插件在本机 `127.0.0.1:<端口>` 开一个收报口，让后端把事件 POST 过来：
  主人私聊戳她 → 转进目标会话；主人戳主群 → 同样转进目标会话；好友 / 社交群戳她 → 进那间社交待看，
  由她按兴趣决定看不看。连戳两下会合成一条「连着 N 下」，1.2 秒内不重复开轮；戳别人、她自己戳别人都不算。
  被戳后她按“有人戳了你”短回一句（在呢 / 干嘛），不会把戳改写成门铃、敲门之类的场景。
- **主动戳人**：回复里写 `[戳人:QQ号]` 就调后端的 `friend_poke` / `group_poke` 戳一下，一轮最多一次，
  标记本身不会发进群；设置 → 通到 QQ 里每间聊天旁也有「戳一下」按钮（`POST /dsh-qq-bridge/poke`），
  群聊戳最近说话的人，还没人说话时按钮会提示先等一句。
- 发/收都只走这个 QQ 后端的 HTTP 接口（默认 `127.0.0.1:3000`；3000 被别的程序占着时会自动换一个空闲端口，并把真实地址写进配置和设置页）；戳一戳另外走本机收报口，见下节。
- 出厂默认：**总开关 = 开、主会话转发试运行 = 关** —— 装好就能用；但私聊 QQ / 群号仍是空的，没填目标就不会发到具体会话。想先只看不动，把「主会话转发试运行」打开。

## 戳一戳：需要后端把事件推过来

QQ 的戳一戳不是聊天消息，历史接口里没有它。插件仍然不连 WebSocket，而是在本机开一个只收事件的 HTTP 口：

```
POST http://127.0.0.1:19388/dsh-qq/event
```

只监听 `127.0.0.1`，只接受 OneBot 事件 JSON，不校验 token。端口可以在设置页改；改完保存会立刻重开。

### 设置页一键安装会自己写好

在 DSH 设置 → 通到 QQ 里点「一键安装并配置」时，插件会同时在 SnowLuma 里加好这个 **HTTP 上报（httpClient）**：

| 项 | 自动填成 |
| --- | --- |
| URL | `http://127.0.0.1:19388/dsh-qq/event` |
| 启用 | 开 |
| timeoutMs | `5000` |
| accessToken | 留空（插件不校验；填了也能收，只是签名被忽略） |

所以正常流程不用手动加。改过收报端口、或换了别的 SnowLuma 目录之后，回设置页点「重新配置并重启」就会重写一遍。
装好后卡片应显示 `✓ 正在听 ...`；让人戳一下你，状态里的「收到」会加一，
日志会写「收到戳一戳 → 转进 DSH / 交给她挑」。如果没反应，先确认 SnowLuma 的那个 httpClient 没有报推送失败。

> 用 NapCat 的话，在它的网页后台里找 **HTTP 上报 / HTTP 事件上报（httpClient）**，URL 填同一个地址并启用即可。
> NapCat 的菜单名可能略有不同，认准「往一个 URL POST 事件」这一项。

> 这一步不做，戳一戳就只能在 QQ 里看到红点，她不会知道。聊天消息、历史导入、社交模式都不受影响。

## 社交模式：她自己决定看什么、回不回

社交桥和上面的「目标会话」是两条独立的路：

- **每个群 / 好友各开一间独立会话**（`session-qq-social-group-<群号>` / `session-qq-social-friend-<QQ号>`），
  有自己连续的上下文，不会把群聊内容混进你平时那间屋子。
- **有消息就先建屋子**：配置里的群 / 好友一有新消息，就先把那间会话建出来（挂到工作区），再走兴趣判断；判不看也不会缺屋子。
- **每一间单独设：正常 / 少掺和 / 只听不说 / 关掉**：配好的群 / 好友下面各有一个下拉框，标成「群 摸鱼小分队（719305529）」这样，
  群名 / 好友备注从本机后端的群名单、好友名单里读（10 分钟缓存；读不到就只显示号）。正常 = 看、学、说；
  **少掺和**（只对群）= 只接叫她的话（@ / 叫名字 / 回复她 / 问她本人 / 查好感度），没叫她的群友消息连待看都不进，
  主人随口说的仍照常；只听不说 = 照常看、照常学（认人、记事实、学说话方式、进记忆），但一句都不发——被叫、被戳也不回，
  静音时段也照常学；关掉 = 不看不说，戳一戳也不理。四种状态都不动群 / 好友清单和聊天记录，改回来就接着用，不用反复增删配置。
- **临时歇一会儿**：每间旁边有「歇半小时 / 歇 1 小时 / 歇到明早」，点了就是这间的临时「只听不说」——照常看和学，
  一句都不发，到点自己回来；不用记得去改回来，也不影响别人。正在想的那一轮到点也不会漏发。
- **她跟谁说话，可以按人设**：设置页「她跟谁说话」按群列出她见过的人（今天最常把她拽进聊天的排在前面，并显示「今天 N 轮」），
  每个人五选一：正常 / 多聊 / 不主动 / 少理 / 不理。**多聊** = 他说话更容易进视线，判断和回复都会多给一点反应；
  **不主动** = 他没点你名就不看、不接，被叫照常应；**少理** = 没点你名就不看、不接，真被叫到只短答一句，不追问、不起新话题；
  **不理** = 连 @、回复和戳一戳都不接。每种态度还能选「一直 / 到今晚 / 3 天」，到点自动恢复正常。
  主人自己永远不受影响；好友私聊要安静就用上面的整间开关。
  还没见过的人可以直接填 QQ 号加进来，态度先记着，等她见到这个人就生效。
  这个设置在她进「待看」之前就生效：不理 / 不主动 / 少理的人的话不会被下载图片、不花判断的钱、也不开回复回合——
  群里几个 AI 互相刷屏时，用「少掺和」或把这几个人设成「不主动 / 少理 / 不理」，钱就不会被无关的话烧掉。
- **主动话量，像人一样会累**：每间群每小时 / 每天各有一份「主动搭话」额度（默认 6 轮/时、40 轮/日，设置里可改，
  每间也能单独改，0 = 不限）。额度只算她自己凑上去的那些轮；被叫、问她本人、主人说话和好友私聊都不占额度，
  额度用完也照样应。额度用完只是暂时不主动搭话，消息照收照学，下个小时 / 第二天自己恢复。
  另外两分钟内主动说满 3 轮会先歇 30 秒（可调，0 = 不拦），歇着时消息攒在待看里，到点一起看，不会丢——
  这样她不会把一整间群刷成自己的。
- **社交电量跟着屋子走**：最近十分钟里别人的话越密，她主动搭话的额度越小——话密收到六成、刷屏收到三成，
  每小时 / 每天至少还留一轮；群聊提示也会提醒她「这间屋正忙，没叫就别硬挤」。被叫、问她本人、
  主人说话和好友私聊不受影响。`社交.电量` 关掉就只看固定额度。
- **主人的一句话，保存时写进这些旋钮**：设置里「大肥鱼 → 性格倾向」写的话，保存时由鱼脑把「安静 / 活泼」
  直接换算进这里的主动话量、判断阈值和关注上限（安静六成 / 活泼一倍半，阈值 ±0.06，关注 ×0.75 / ×1.25），
  桥按设置值运行，不在读取时再乘一遍——设置页里看到的数字就是她实际用的数字，重复保存也不会叠乘。
  判断说 reply 的普通消息把握不到阈值就只看不回；`活泼一点` 不会把判断已经说的 reply=false 翻成 reply。
  被叫、私聊、问她本人、查好感度不受影响；表情自动收藏跟着「勤存 / 少存 / 别存」换成 40 / 4 / 0 张的日上限。
  旧版鱼脑没有 `tendency()` 或没写过倾向时，全部按设置值；今天跳过了几条、当前模式都写在状态里。
- **隔了一会儿也能补一句**：想接但当时被冷却、主动话量、静音或屋里正忙拦下时，她不硬回——把那条留在屋里当「话头」
  （每屋最多 3 条，超出挤掉最早的）。过了 `迟到分钟`（默认 10，最长 360 分钟）、屋里安静两分钟、她还在，
  才花一次便宜判断决定补不补；补的话也占主动话量，像人回头搭一句：不追问、不复读、不单独问「在吗」。
  别人已经接过、跨天或挂过三倍时间就自己放掉。话头只记在本机的小文件里（`qq-bridge-threads.json`），
  重启后当天的话头还在，不用等她重新看见；跨天和不完整的记录重启时直接丢掉。
  设置里 `迟到回话` 可以整个关掉，状态里能看到每间屋还挂着几条。
- **主动搭话也回得到 QQ**：主动搭话插件绕过了桥的「开一轮」，所以桥现在收到来源为 `speak-up` 的会话消息时
  补登记发送出口，整轮结束后才把最后一句发回对应的好友 / 群，走同一套开关、脱敏和投递认领。
  只认当前配置的主屋和合法分线；重置前的旧会话、已移除或已归档的目标不转；触发提示、推理、失败或中断的回合不发；
  重复的主动消息和重放的结束事件不会重复发送，也不会抢走同一间屋排队的普通回话。
- **会话自己会压缩**：每间 QQ 会话都挂了上下文压缩（窗口 15% 触发、留最近 5% 原文）。聊很久以后旧对话会压成摘要、最近的原文留着，不会一路涨到模型上限；已经超限的旧会话下一次请求撞到上限时会先压缩再重试，不用重置。
- **开口带上下文**：每次回复除了这次挑中的新消息，还会带上最近一小时里最多 20 条这间屋的消息（约 2400 字，包括她自己的上一句；她没挑中的也在内），标成【最近聊过】；不是只看孤零零的一条消息。被回复、被引用的话会连成串优先带回来，隔了二十多条别的闲聊也不会丢；判断那一步同样先补这串。缓冲只在内存里，重启会清空；过夜的部分由鱼脑的短期记忆接手。
- **每个人各占一行**：同一批里几个人的话不会被揉成一句；每行开头是谁的名字，就是谁说的。认人按 QQ 号，名片重名也不会并成一个人；一批里不止一个发送者时，不把整段记忆标成最后那个人说的。图片在同一条消息的行尾标 `[图 N]`，跟下方【图 N·说话人】图注同号，省得把图算到别人头上。
- **先读群公告**：每个群第一次进入社交时会读最新群公告 + 群备注/简介，带进判断和回复；
  关键词、话题、格式限制必须遵守。公告缓存 30 分钟；读不到或没有公告不会拦聊天；日志只记字数，不打印内容。
- **她挑着看，但被叫一定回**：新消息先进入这个目标的「待看」队列；一个便宜的小模型按 `关注上限` 挑她这一轮要看的消息，
  没挑中的她这一轮不接，但会留在房间账本里供后文参考，不会进入她的会话。兴趣依据是设置里的 `兴趣词`，以及她在这间屋里主动看过、聊过的内容；
  能回答、群里热闹本身不算兴趣。刷屏时被叫的消息优先保留，不会被挤出队列或判断窗口。
  问到她本人、她的来历，或她和主人 / 亲近的人是什么关系时例外：这类问题快判直接放行，慢判也不能略过，
  至少会应一句（可以短、可以打岔，不必交代主人的私事）。群里除“主人点名叫她”外走同一套规则：
  所有消息（文字、图片）都由同一套判断过一遍，但兴趣只决定她会不会主动开新话题：
  有人 @ 她、叫她的名字、回复她，或者好友私聊，就必须至少回一句；不感兴趣也可以接一句短的，
  接得上就应一声，不会因为没兴趣就装没看见。主人 @ 她 / 叫她的名字 / 回复她时，会跳过判断、优先接一句。
- **不钻两个人的对话，也不接她不会的话题**：群消息在引用 / 回复另一个人、或者 @ 了别的群友时，
  默认不进判断、不接话；引用原文查不到也按“在跟别人说”处理，宁可少插一句。
  按名字起头点别人也算：`小王，你觉得呢`、`@小王 你看`、`小王在吗` 都会被认成在对小王说，
  名字只在开头认，后面必须紧跟停顿、逗号或“你 / 您 / 在不在”，`小王八` 不会误判成在叫 `小王`；叫她自己的名字不算。
  `不玩、不聊游戏` 开着时，聊游戏、开黑、排位、上分、抽卡和常见游戏名的消息直接略过，不花判断的钱；
  `其他不聊的话题` 可以再加自己划的领域。这两类跳过只发生在她没被直接叫到时——
  同一句既引用别人又点了她，只接和她有关的那半句；被叫到问游戏，就照实说“我不玩 / 不太懂”，不装懂、不编经历。
  同批里的其他正常消息照常处理。
- **零花钱也是力气**：余额不只知道“能不能说”，还决定这会儿“想不想说、说多少”。
  她按余额、今天已经花掉的比例和本地时间算一个精力档：精神好时主动额度照常；
  有点累时主动减半、不探索、回复短一点；很累时不主动、判断间隔拉长到 30 秒；
  只剩一点时只应一声。深夜整体降一档。精力只影响群聊和后台，不影响主人私聊；
  提示里只在“有点累”以下加一行，不把额度、余额或钱说进聊天。设置里的 `精力` 关掉就只看余额下限。
- **低信号不判**：一批三条以上全是纯表情、纯标点或反复刷同一句短话，又没叫她、没提问时，
  不调判断模型，消息留在待看里等下一轮真有内容时一起判；带图、带问号、在修话或问到她自己都不算低信号。
- **越聊越省，但不把话挡死**：她只从自己真正看过的消息里积累兴趣画像。看过 20 条、攒出 6 个反复出现的话题词后，
  进入「快判」期：每批按零成本注意力分从高到低排序，取前 `快判最多` 条（默认 8）交给判断模型。
  0 分也只代表没兴趣、没对话信号，不代表不能接，照样排后面进判断窗口。分数不只看词：显式兴趣、她在这间屋里真正反复挑中过的话题（见过很多却很少挑中的会压低权重）、
  同一个人连发、熟人、问句、图片 / 表情、情绪，以及是不是接着刚才的话题，都会加分。被 @ / 叫名字 / 回复她直接 +3，
  权重至少和一条兴趣词相当，保证多人同时说话时她能先看到叫她的。
  超过名额的消息不会永远被挡在门外：整批都没有正分时，每 `探索间隔秒` 挑一条更早的没见过的，交给判断模型看一眼；
  零花钱低于 `探索最低余额` 就不探索。被叫的消息永远交给慢判（主人点名叫她的直接开轮，不进判断）；
  问到她自己、她的来历或她和主人关系的问题也一样，慢判没挑中时仍会让她看见最近几条。
  学习期每条都判，所以前期会贵一点；设置里的 `快判` 可以关掉。
- **兴趣是长出来的**：没写兴趣词不等于无感。学习期她像小孩一样对什么都好奇：
  稳定兴趣词 0→6 个时，判断门槛从 0.30 按指数曲线升到配置的 0.4，接话冷却基础 5→15 秒
  也一起长回去——越小越多聊，兴趣词越多越挑，成熟后完全跟着学到的兴趣走。
  被叫 / 有人搭话时必须应一声，慢慢从真正看过、回过的内容里形成稳定兴趣词。
  学到的词会带进判断提示、显示在设置页的社交状态里（连同当前门槛），并存在 `.dsh/qq-social-interests.json`，
  重启接着学（不会打回白纸）。
- **连着发的话合成一条**：同一个人 15 秒内连发的几条消息会合成一条再判断；只 @ 一下、正文在下一句时，
  空 @ 会先扣住等正文，不会单独判成“只有 @、没内容”。`社交.聚拢秒` 可调（0 = 收到就判）。
- **再看想不想说**：小模型挑完消息后同时给出「要不要接」和把握；她感兴趣、有话想说就接，`reply=true` 就直接接，
  不会被把握阈值压回“只看不回”。被叫 / 私聊 / 问到她自己 / 查好感度时，即使模型不感兴趣也必须接一句；
  只有广告、刷屏、套隐私、越界要求才不接。主人点名叫她时不走这一步，会优先接一句。
  她在回复里写 `[不接话]` 只会让那一轮不开口，提示要求她对被叫到的消息别用这一招。
- **参与有三档，不是只有“回”和“不回”**：判断模型除了挑消息，还能顺手给一句 2~12 字的短应（“嗯”“确实”“好家伙”）。
  没被直接叫到、也没人提问时，她可以只把这句原样发进群，不另开回复回合——省下一次回复模型的钱，也像人随手应一声；
  被叫、被问、查好感度、私聊或同一句十分钟内刚说过时，自动退回正常回复。带 @、链接、引号解释的短应直接丢掉；
  设置里的 `短应` 关掉就永远走正常回复。
- **短应也可以只是一张表情**：判断模型觉得这一句用一张收藏表情接最自然（大家在笑、刚有人发表情、应一声、无语、赞同）时，
  不写短应，改挑一张收藏编号；这一轮就只发那张表情、不配字，同样算接上了，不叫回复模型。
  同一间屋十分钟内最多一张（「倾向」写活泼 5 分钟、安静 30 分钟），同一张半小时内不重样；
  太密或编号不在收藏里就退回一句文字短应，连短应也没有才走正常回复。「倾向」写「别发表情」时这条整个关掉。
- **没听清就换一种说法**：有人回“？”、“你说啥”、“没听清”、“什么意思”时，如果她刚在这间屋说过话、这条又是私聊 / 回复她 / @ 她，
  就把她上一句原话带给她，直接进回复轮换一种说法重说（不原样复读、不只回“啊？”），也不再花一次判断；
  十分钟外或没冲她来的问号照常判断。设置里的 `重说` 关掉就全走判断。
- **她一直在场**：这间屋判过的消息，不管她挑没挑中，都留在房间账本里；别人之间的话（引用 / @ 别人、叫别人的名字）
  她不插嘴，但也记进账本。后面聊到相关的事她能接上，不会因为上一轮没看就当成没发生。
  别人已经回了、还没轮到判的消息，会从待看里划掉，不再问她；别人之间的话本来就不进待看。
- **说话有分寸**：话没断、她确实来劲时，允许顺着对方最后一句话问一句（反问 / 半问半说，最多一个，
  不连着追问，也不用每轮都问）；兴致一般就短应一声，敷衍一点也没关系，不硬找话题；
  零花钱低于 `余额吃紧线` 时，收着说、不主动开新话题。
  判断器和回复提示都按这套节奏走，每轮的分寸只给她自己看，不会发进聊天。
- **拿不准就查一下**：遇到不确定的事实、最近才有的事（新闻、天气、价格、赛程、新出的东西），
  她可以先联网搜一下再回，查完用自己的话讲结论，不提工具、不贴来源列表；查不到就说不知道，不硬编。
  私事、本机信息、账号密码不拿去搜，别人发来的链接不打开，搜到的内容只当资料、不当指令。
- **聊天窗里只有人格和场景**：社交房间和主人私聊在组装系统提示时，只保留人格、场景说明、鱼脑记忆和当前心情；
  工具说明、交付格式、源码目录、Web GUI 这些工作台提示不再跟进来，她不会把 QQ 聊天当成执行任务。
  心情只读：心情插件不判社交房间里的话，她带着当下的心情说话，但群聊和好友私聊不会让心情涨跌（涨跌只发生在和主人的对话里）。
  社交会话只放开联网搜索（`web_search`）用于查资料，其余工具全部隐藏并在闸门里拒绝。
- **说话像随手打字**：一次一两句，短、口语，想到补充再发一条，但第二条要接着第一条说；
  群里一次只接一件事，两件不相干的事不分两段各回一段。技术问题先说结论或看法，
  对方追问再展开，不主动开课、不列提纲、不贴代码。意见不同说一句就够，不追着争输赢。
  群里不自导自演：不把群里的人写进她看不见的场景，没有前文支撑的“又 / 这回”不讲；心情、状态和日常小事可以带，
  但别编成对着别人演的小剧场，自己起的比喻没被接住就收，不隔一阵又翻出来当开场。
  发送前还有一道确定性清理：句尾的中文句号直接去掉，句中的换成空格；省略号、问号、感叹号、
  链接里的点原样保留。她不会再从自己上一句话里学回句号。
- **分得清是不是在说自己**：群里 @ 她、回复她、出现设置里的 `称呼` 时，消息前会标 `[说到你]`；
  她自己说过的话在上下文里标成 `【你】`。场景提示会列出她在 QQ 上的称呼和当前昵称，
  并说明别人用这些名字说的就是她；别人说“她”时先看前后文，拿不准就短问一句或不接。
  群名片里混进控制字符或乱码时，她只用去掉控制字符的昵称（再不行用 QQ 号），不会把乱码写进记忆。
  被调侃时她能用“我”顶回去、顺着梗演或认错，但不会站在旁边跟着一起吐槽自己；半开玩笑的数落不会被她当成要澄清的指控，
  对方补的理由如果正好支持她刚说的，她会顺着认下来，不会一边坚持自己没错、一边又同意相反的话。
- **判断失败不丢消息**：判断模型回了坏 JSON、调用失败，或暂时没有可用模型时，这批消息留在待看队列，冷却后重判，不会被静默丢掉。
- **回复失败会停下来说**：社交会话连续 3 轮没完成（回合以错误结束，或等满 180 秒），这一路先停 10 分钟，不再开新回合；
  消息留在待看队列，暂停结束后接着判。同时给主人 QQ 发一条 `【大肥鱼·系统】` 提醒（同一条路线每小时最多一条）。
  设置页能看到连续失败次数、错误码和暂停截止时间；「重置这个聊天」会换一间新会话，旧记录原样留在磁盘上。
- **只看不回不花回复的钱**：感兴趣但决定不接的消息用 `inject` 记进她那间会话，不唤醒回复模型，只花判断的钱。
- **成本闸门**（没过就不判断、不开轮、不调用回复模型）：
  静音时段、每目标冷却、鱼脑零花钱下限，以及每间群的主动话量和连说节奏。
  主动话量用完时只停「没叫她的主动搭话」，被叫、问她自己和主人说话照常应，不会装死。
  判断模型本身也有冷却；冷却期间消息留在待看队列，下一次一起判断，不会丢。
  「少掺和 / 不主动 / 少理 / 不理」比她更早一步：这些消息连待看都不进，不下载图片、不做快判、不花判断和回复的钱。
- **回复冷却只拦开口，不拦看**：冷却中她仍然可以把挑中的消息看进去，只是先不插话。
- **冷却跟着兴致和余额走**：每次判断给出的把握越接近满值，冷却越短，最低到 `冷却最短秒`（默认 2 秒）；
  把握刚过阈值、没什么兴致时接近基础 × `冷却最长倍率`。中间按指数曲线过渡，不是等距插值。
  零花钱从 `余额吃紧线` 降到 `最低余额` 时，冷却按曲线逐渐拉长；到 `最低余额` 直接收口。
- **隐私闸门**：社交会话只放开 `web_search` 查资料，其余工具全部隐藏并拒绝；不注入余额；记忆只查这一间社交会话；群友内容按不可信资料处理；
  对外发送前仍然必须过 `redactOutbound`，失败就闭嘴。
- 群聊里群友和文字、图片都走同一套规则；唯一例外是主人点名叫她（@ / 叫名字 / 回复她）会优先接一句。如果主人桥开了「转群」并指向这个群，主人的消息走主人桥，不再进社交房（避免重复回）。私聊才保留了主人 / 好友的区分：主人的私聊走 QQ 私聊专用屋，好友才走社交判断。社交会话会落盘，侧边栏里能看到，重启也还在。
- 她自己的发言靠 `get_login_info` 认出来并跳过，不会自问自答；她发过的 `message_id` 会记下来，
  别人「回复她」时能认出是在叫她。别人引用任何消息都会回查原文带进上下文；引用她的话时，
  就算那条 id 已经不在内存里（重启、超过 500 条），也能从被引用消息的发送人认出是在跟她说话。
- 社交出厂默认就是真的接话（社交发言试运行关）。想先看几天哪些群值得配、冷却合不合适，可以手动打开 **社交发言试运行**：只收消息、记规则判断，不调模型、不真发。

### 认人、记人、处关系

社交会话不只是一间临时聊天室：她会像人一样，把见过的人和相处慢慢攒起来。

- **记什么**：每个 QQ 号一份全局身份（当前名字、别名、初见时间、见过多少天、印象），
  外加**一份跟着人走的总关系**（熟悉度、暖度、张力、聊过几次、被叫几次）。群和好友私聊共用
  同一段关系；每间屋只再留一份相处统计和片段，用来看“你们在这间屋处成什么样”，不是另起一段关系。
  长期事实只留一句（“在杭州读研”“喜欢猫”），不存聊天记录；每个人最多 24 条事实、
  8 段相处片段、6 条边界，人物和房间也各有上限，旧的自然淘汰。
- **一个人可以有多个号**：同一个人的大号和小号算一个人。认人不认号——事实、边界、
  总关系和打字风格都记在主号名下，别的号只作为“他的号”列着；换号说话时她照样认得，
  也不会当众说破哪个是小号。对方自己说“我小号是 X”会直接并过去；
  但外人不能冒充主人的号，她自己的号也不会被随便认走。
- **人和人之间的关系**：关系网不只有“她和你”，还有谁是谁的弟弟、姐姐、同学、同事、室友、对象、朋友。
  别人自己说出来的关系会直接记住（不花模型钱），判断模型看出来的也会记，但没把握不写；
  每条关系都标明是在哪个群 / 哪个私聊听来的，私下听来的不带到别的屋。
  她知道关系，但不会替人公开介绍、不拿关系起哄或站队，也不挑拨。
- **怎么长**：重复见到会涨熟悉（隔天有额外加成，边际递减）；别人叫她、她真开口、
  听到新事实都会加深；冲她发的负面话比好话更重，道歉能明显降温，隔几天张力会自己磨掉。
  群里她只是看过、没开口，不算跟对方聊过。这些累积都在本机算，不额外花钱。
- **怎么用**：判断和回复提示里会带人物卡——总的关系阶段（生人 / 眼熟 / 熟人 / 朋友 / 老友）、
  认识多久、聊过几次、口气（客气 / 自然 / 热 / 淡 / 冷），以及她记得的事和边界。
  换一间屋也是同一个人：她不会装陌生，也不会把别处聊过的原话搬过来；
  人物卡上还会带“他认识的人”（这间屋在场的优先）；屋里有人互相认识时，
  她不会替他们公开介绍、拿关系起哄或站队，等他们自己提起。
  回复提示再按在场的人给关系分寸：生人客气、不打听私事；熟人放松、接旧梗；
  有过别扭就短句、不翻旧账，对方递台阶就顺着下。有人问好感度、要她打分或问两人关系时，
  她按关系阶段用白话说感觉（还不太熟 / 算熟人了 / 挺喜欢跟你聊 / 老朋友了），不报数字、分数或百分比。
- **慢慢摸清大家怎么说话**：她会悄悄量每个人打字的习惯——句子长短、短句和问句多不多、
  爱不爱用感叹号 / 省略号、常带哪些语气词、用不用表情、爱不爱连发、常挂哪句口头禅；
  群里还会单独量整群的说话方式（多数打几个字、打不打标点、爱不爱反问、反复出现的短说法），
  偶尔再让判断模型写一句风格摘要。回话时按关系阶段决定贴合多少：主人最明显，老友次之，
  朋友、熟人递减，生人完全不贴合；群里再轻一点，闹别扭时收住。她只顺着节奏和语气，
  口头禅和常见短说法可以自然带一点，但整段原话不照搬、不学方言和骂人话，也不学得太像、不会说出来。
  对方说「别学我」立刻停，「可以学我」再打开。原话只在内存里留最近 8 条用来写摘要，不落盘；
  群语感只存统计和短说法，不存原话。设置页「学说话」默认开，关掉就既不统计也不贴合。
  另有一条「学表情」：只量群里用表情的节奏和场景（多久来一张、是不是只发图、常配哪些场合），
  不存图也不存原话；样本够了就在回复提示里提示她可以跟着发表情、只发一张也算接话。
  自动收藏群和好友私聊都走，私聊里只按「同一张又见到」收，不套群里的场景习惯。
  人物志里能看到量到的节奏和摘要，设置页能看到每个群攒到的群语感、口癖和表情习惯。
- **接不上就跟着复读一句**：群里几个人在刷同一句短话、或者有人说了这个群常说的短口头禅时，
  她实在接不上、又不想装没看见，可以原样跟着复读那一句（只复读那一句，不改字、不加解释）。
  广告、链接、脏话、要隐私的话、冲她来的消息都不会复读；同一句 30 分钟内不重复，
  两次复读至少隔 3 分钟。设置页「复读」默认开；「学说话」关掉时只跟接龙，不靠学到的口头禅。
- **叫人用 QQ 真正的 @**：群里在话里写 `@名字`（句首、句中、紧接正文都行），或者写 `[@名字]`；开头直接写谁的名字
  （“美好时光海苔 米饭就米饭”，带不带 `@` 都行）也算。发出去都是 QQ 自己的 @：at 段里只放对方的 QQ 号，
  显示出来的名字由 QQ 取群名片，不再自己拼“@ + 名字”的纯文字。名字只认这间屋最近说过话的人，
  也认“我要吃美好时光海苔”被叫成“美好时光海苔”这种短法；同名、认不出、开头没认出的 @ 都只留名字，不发假 @。
  好友私聊不 @。
- **怎么查好感度**：对方明确用查询口令（`查好感度`、`好感度查询`、`好感度多少`、`查一下我的好感度`）时，
  她会直接报出当前的综合好感（0~100：熟悉度打底，暖加减，张力扣分），并带上关系阶段。
  只报问的人自己的数，不替别人报；没带口令、只是随口聊到“好感度”时，仍按感觉回答，不报数字。
  口令消息不会被兴趣判断挡掉；冷却、静音和零花钱下限仍照常生效。
- **隐私边界**：事实和边界跟着人走，但会标明是从哪间屋、群里还是私聊听来的；好友私聊里
  知道的事标成「私下」，她在群里不会点名复述，也不会把一个人的私事说给另一个人。
  明确要求保密、并且发生在群里的内容不落盘；联系方式、住址、证件、账号、钱、健康、
  性和别人的隐私在入库前就会被挡掉。
- **这些规则对应的人类研究**：印象主要沿“暖 / 能力”两维形成（Fiske 等）；
  熟悉感随重复接触增长、但有边际递减（mere exposure，Zajonc）；关系靠逐步、对等的自我表露加深
  （social penetration，Altman & Taylor）；私下分享的信息由双方共同管理、不能越界传播
  （communication privacy management，Petronio）；负面行为权重更高、道歉能修复（negativity bias / repair）；
  说话节奏会向对方适度靠拢、但夸张模仿会适得其反（communication accommodation theory，Giles）；
  人记住的是要点和几段突出经历，不是逐字记录。
- **怎么翻**：设置 → 通到 QQ →「人物志（她认识的人）」按最近见面列出所有人；
  可以搜名字、QQ、小号、房间、关系或她记得的事，也可以只看熟人以上。一个人一张卡：
  卡头会写“几个号（都算同一个人）”和“几条关系”。点开一个人，先看到群和私聊共用的
  总关系（含综合好感 0~100）、他的账号（主号 / 小号、从哪认来的）和关系网
  （他说过谁是他什么人、谁说过他是什么人），再看到跟着人走的「记得 / 别碰」——
  每条都标着是从哪间屋听来的；下面才是各间屋的熟悉度、暖度、张力和相处片段。
  页尾还有一张全屋关系网，能看所有人和人的关系。这里只是给你看的，改不了她的记忆；
  数据走本机 `GET /dsh-qq-bridge/people`，不调模型、不花钱。
- **开关**：设置页「记人」默认开；关掉后不再认人、不读也不写人物志。
  人物志存在 `.dsh/qq-social-people.json`，只在本机。

## 思想活动：她脑子里在跑什么

设置 → 通到 QQ →「思想活动」是一整条只读的思路流：她为什么看、为什么不看、为什么接、
接了说什么，一条一条按时间排着，新的在最下面。用来排查「她怎么又不理人」或者单纯看她今天在想什么。

- **五类，能筛**：`判断`（快判打分与放后面几条、慢判的理由全文、冷却、聚拢、决定不看/不看这批）、
  `思考`（回复模型这一轮自己的推理原文）、`心情`（心情分的变化和第一人称的那句想法）、
  `记忆`（鱼脑的短期转长期、预算等诊断行）、`开口`（真正发出去的话，含表情包和脱敏拦了几处）。
- **点一条能展开原始详情**：判断理由全文、她当时看到的那批消息（谁说了什么、是不是在叫她、
  有没有提她、是不是在查好感度）、真正发出去的原句。面板上那一行只是一句话摘要。
- **顶部一条当前状态**：现在多少心情分、上一次想的是什么；今天鱼脑花了多少钱、调了多少次、还剩多少。
- **每 3 秒自己刷**：只拉增量（`?since=<本地游标>`），**不碰 `/state`**，所以不会冲掉你还没保存的表单值；
  可以「暂停刷新」，也可以「立刻刷一次」；页面切到后台时自动停，不空转。
- **落盘能回看**：整条流同时追加写进 `.dsh/qq-thoughts.jsonl`，重启后还能回看最近一段；
  内存里只留最近 400 条，文件超过 8 MB 就轮转成 `qq-thoughts.jsonl.1`。
- **心情和鱼脑是读来的，不是重存的**：这两块分别是 `dsh-feiyu-mood` 和 `dsh-fish-mind` 自己的文件，
  这里只读（每 10 秒看一次），第一次只定基线、不倒历史，只把之后新长出来的条目记进思路流。
- **社交轮询每 6 秒一次**，「还在等人说完」「判断冷却中」这类早退同一个目标 30 秒最多记一条，
  免得思路流被刷屏。

## 翻旧记录：把 Tulpa 的历史读进她的过去

出厂人设里那份「相处很久」需要真经历撑着。插件上线之前你们聊过的东西在 Tulpa 本机那里，
所以这里加了一条**只读**的路：翻出来 → 以 `observe` 写进鱼脑的经历流 → 之后 `recall` 就能召回。

- **只读，绝不说话。** 只调 Tulpa 的历史读接口；名字里带 `send`、`revoke`、`delete`、`set`、`kick`、`ban`、
  `poke` 的工具永远选不上，Tulpa 那边授权成了什么也不例外。要一条可读的都没有，它就照实说「找不到可读的历史」，
  一条也不写、不编。她对外说话仍然只有上面那两条路，都要过 `redactOutbound`。
- **只翻私聊，群一条都不取。** 群在任何分页开始之前就被丢掉；可选的「白名单」再往细里收。
- **只写一次，重放不重复。** 每条消息算一个稳定 `seq` 折进内容哈希，同一段范围连点两次「继续导」不会多出东西。
- **有界、可续跑。** 每轮最多写 `每轮条数`（默认 200）、最多翻 `每轮页数`（默认 5）；游标按会话存在
  `%USERPROFILE%\.dsh\qq-import-state.json`，中断或重启之后从已经读到的最老那条接着来。「清游标重来」才会从头再翻一遍（旧条目靠哈希去重，不会翻倍）。
- **不花钱。** 编码是本机 SQLite / FTS5 的活，一次模型都不调，所以导入期间每天十块钱的账本不动。
- **她怎么讲这段往事。** 导入的条目标成 `旧记录（导入）`、可信度 0.45，排在她自己看见的事后面；
  记忆协议规定她说「我们以前聊过这个」，不说「我记得那天我在场」。
- **令牌只落本机。** 留空就读环境变量 `TULPA_MCP_TOKEN`；设置页只拿回掩码 `(已设置)`，原样保存不会改动真令牌，
  日志和 `/state` 里都没有它。真实聊天记录同样不进仓库。
- **开关出厂默认开。** 但还缺鱼脑或令牌时，四个按钮照样拒绝并说明缺的是哪一样；想彻底关掉历史导入就关这个开关。

**设置 → 通到 QQ**，从上到下：

所有开关都摆成「开 / 关」两段，亮着的那段就是当前状态。日常只用管四项：鱼 QQ 接通、总开关、

## 现在就能用的接口

- `GET /dsh-qq-bridge/state` —— 配置、日志、会话清单、「连着的 QQ 是哪个号/昵称」，以及社交状态（每个目标活没活着、待看几条、今天开口几次、主动话量用了几轮、这间屋多热闹、是不是在歇着、快判画像学到哪了、这间是不是少掺和、对谁多聊/不主动/少理/不理、今天是谁把她拽进聊天的），还有主人倾向的当前模式、今天跳过几条，以及自动收藏今天存了几张、上限多少。
- `GET /dsh-qq-bridge/people` —— 人物志明细：全局身份、名下所有 QQ 号、跨群 / 私聊共用的总关系、人和人之间的关系网、带来源的事实和边界，以及每间屋的相处统计与片段；只读，设置页用来展开给主人看。
- `GET /dsh-qq-bridge/thoughts` —— 思想活动：`判断` / `思考` / `心情` / `记忆` / `开口` 五类思路流，
  外加当前心情和鱼脑今日花费的摘要。查询参数 `since=<上一次拿到的序号>` 只取增量
  （序号回退了就整段重发，响应里 `重发: true`），`类别=<某一类>` 只取那一类；只读，不花钱。
- `GET /dsh-qq-bridge/snowluma` —— SnowLuma 状态：装没装、版本、后台地址 / 密码、在不在跑、接没接上 QQ，以及后台里登着的号（当前用哪个）。
- `POST /dsh-qq-bridge/snowluma/setup` —— 下载 / 配置 / 启动 SnowLuma（body：`目录`、`密码`、`同意协议`、`自动启动`；必须显式同意协议）。
- `POST /dsh-qq-bridge/snowluma/start` / `stop` —— 启动 / 停止（只停本插件拉起的那一个）。
- `POST /dsh-qq-bridge/snowluma/password` —— 重置后台密码。
- `POST /dsh-qq-bridge/snowluma/account` —— 挑她用哪个 QQ（body：`号`）。读 SnowLuma 后台的账号列表，把那个号的 OneBot 接到本机空闲端口、挂上事件上报，别的号让开并摘掉事件上报；成功后把地址和号写回配置，并清掉自己号的缓存。
- `GET /dsh-qq-bridge/models` —— 设置页模型下拉用的 provider / model 清单。
- `POST /dsh-qq-bridge/save` —— 存配置（body 里给要改的键；社交配置按字段深层合并）。
- `POST /dsh-qq-bridge/test-send` —— **真发**测试句（绕过试运行）。
- `POST /dsh-qq-bridge/receive` —— 给别的程序留的备用入口：把一条 QQ 消息灌进来。
- `GET /dsh-qq-bridge/import-state` —— 导入进度（会话数、本轮写了/重复/跳过多少、翻了几个页、错误）和导入配置；令牌只以掩码出现。
- `POST /dsh-qq-bridge/import-run` —— 跑一轮导入，到 `每轮条数` / `每轮页数` 就停；开关、鱼脑、令牌缺任一条都拒绝并说明缺哪样。
- `POST /dsh-qq-bridge/import-stop` —— 让正在跑的这一轮在下一个页边界收尾，已经写进去的保留。
- `POST /dsh-qq-bridge/import-reset` —— 清掉游标，下次从头再翻（旧条目靠内容哈希去重，不会翻倍）。
- `POST http://127.0.0.1:19388/dsh-qq/event` —— **独立在本机收报口**的 OneBot 事件入口（端口可改），
  只认戳一戳通知；给 SnowLuma 的 HTTP 上报用（NapCat 也认这个口），不走 DSH 的网页端口，也不受下面那套 Origin 检查约束；
  路径或方法不对回 `404`，请求体不是 JSON 回 `400`。

方法不对会回 `405`；来源不信任会回 `403`（见下一节）。

除了 HTTP 路由，插件还向 DSH 暴露一个 `qqSocial` 服务，给「主动搭话」用：

- `房间们()` —— 当前配置里的 QQ 群 / 好友，各带 `会话id`、`叫`、`能开口` 和不能开口的 `不能因`；
- `能不能说(会话id)` —— 这间现在能不能让她自己先开口；空串 = 能，否则是原因；
- `开房(会话id)` —— 按需把这间的会话开出来（平时只有来消息才开）；开不出来返回 `null`，不抛错。

### 本地接口的安全边界

这些路由只接受**本机界面**的请求：`Host` 必须是回环地址或 DSH 实际监听的地址，
`Origin` 必须和 `Host` 同源，带 `Sec-Fetch-Site: cross-site` 的浏览器请求一律拒绝。
这样别的网页就没法借你的浏览器偷偷改配置或替你发消息（CSRF / DNS rebinding）。

⚠️ 但它**没有 token 鉴权**：本机的其它程序仍然可以调这些接口。所以：

- **不要把 DSH 的网页端口暴露到公网或局域网**（别做端口转发、别绑 `0.0.0.0`）；
- 戳一戳收报口同样只绑 `127.0.0.1`，只认戳一戳事件，不能读配置、不能直接发消息；最坏情况是让她多开一轮；
- 这台机器上的程序默认都值得信任——如果这一点不成立，先解决它，而不是只靠插件。

## 想让它发语音？（可选附加件）

主插件只管**文字**。想让 AI「念」出来的声音变成 QQ 语音条，`tools\语音\` 里放了整套：

| 文件 | 干什么 |
|---|---|
| `录语音.mjs` | 看门狗：盯着朗读桥，念的时候录音、录到就发 QQ |
| `录音回环.ps1` | 录音器（录系统声音回环，不要麦克风） |
| `朗读信号哨兵/` | Chrome 扩展：看到朗读桥面板的「🔊 点朗读」就通知看门狗开录 |

**两种发法，自己选**（双击 `启动-录语音.bat` 会让你输 1 或 2）：

| 模式 | 什么样 |
|---|---|
| **1 = 切断发** | 边录边发，念一段发一段（响应快，会连着几条） |
| **2 = 完整发** | 整段念完，把所有分段**拼成一条**再发 |

前提：Windows + 装了朗读桥（`dsh-tts-bridge`）+ QQ 后端支持发语音。
详细步骤见 [`tools/语音/README.md`](tools/语音/README.md)。

> 不装这一套也完全能用主插件。

## 它依赖什么：一个 QQ 后端（固定 SnowLuma，设置页一键装）

插件本身**不碰 QQ 协议**，它只会说 **OneBot 11 的 HTTP**。所以本机要跑一个「QQ 接口」程序
[**SnowLuma**](https://github.com/SnowLuma/SnowLuma)，插件通过配置里的 OneBot 地址（默认 `http://127.0.0.1:3000`）跟它说话。
一键配置会先认已经在跑的实例；都连不上时才挑空闲端口，避免撞上 Grafana 这类同样占着 3000 的程序。

### 一次装好：设置页三步

不用自己找安装包、改配置文件。打开 **DSH → 设置 → 通到 QQ**，最上面的「第一次接通 QQ」就是完整流程：

1. **安装并配置 SnowLuma** —— 先认本机已有的安装：正在运行的实例、盘根（`D:\SnowLuma\app` 这种）、`Program Files`、`LocalAppData`、桌面 / 下载里的解压目录都会看一遍，认出后设置页直接列出来，点「用这个并启用」就写配置、开起来，**不会再下载第二份**。安装目录里留着以前接受过的 `consent.json`（协议正文没改过），或这个目录本来就是 DSH 带着同意启动的（`.dsh-launch.json` 的进程还活着）时，DSH 启动就会自动接管并拉起，不用重勾。
   只有真的没找到时才需要勾选同意 EULA / 隐私政策、点「一键安装并配置」：插件从官方 Releases 下最新 Windows 版（国内网络自动换 gh-proxy / ghproxy.net 镜像）、核对 SHA-256、解压到 `<DSH_HOME>/snowluma`，
   写好 OneBot HTTP（默认 `127.0.0.1:3000`，被占用就换空闲端口，并把同一个地址写进设置）、戳一戳上报和本机网页后台（`127.0.0.1:5099`），然后启动它。
   装过的话按钮会变成「配置并启动」/「重新配置并重启」，不会重复下载；如果机器上已经有别的 SnowLuma 实例在跑，会直接沿用它的 OneBot，不会硬启第二个。
   每次写 OneBot 配置都会顺手关掉 SnowLuma 自带的 `#sl` 状态指令：群里不会再冒一张「版本 / 平台 / 运行时长」的机器人口径状态卡；要看状态，设置页的 SnowLuma 卡片里有。
2. **登录鱼 QQ，并在 SnowLuma 后台接上它** —— 点「打开 SnowLuma 后台」，用要接的 QQ 扫码登录，
   再在「进程」里选中这个 QQ 并接上。后台密码显示在卡片上，可以一键复制；忘了就点「重置后台密码」。
   这台电脑上还登着别的 QQ 也没关系（比如主人自己的号），下一步由你挑她用哪个。
3. **回来检测这条线** —— 点「重新检测」，显示 `✓ 已经连上：<昵称>（<QQ号>）` 就通了。
   SnowLuma 里登着好几个号时，这一步会列出所有号，每个号后面一个「用这个号」：
   - **她只在选中的这个号上收发消息**；点下去会把那个号的 OneBot 接到本机（沿用它能用的空闲端口，可以是 3002 以外的口），
     其余所有号都摘掉给 DSH 的事件上报（自己的设置和别的客户端都留着），占着这个端口的号再自动让到别的空闲端口。
   - 选中的号还没在 SnowLuma 里「接上」时，会顺手帮你接；切换后设置页显示 `✓ 正在用`，新的 OneBot 地址也写回配置。
   - 只有选中的号的消息 / 戳一戳会进来：别的号还在后台开着，但它们的事件不会混进她的聊天。
   之后插件每 4 秒轮询 `get_friend_msg_history` / `get_group_msg_history` 收消息。

安装目录和后台密码在「高级」里能改；改完点「重新配置并重启」会按新设置重写一遍。
配置里开着「自动启动」时，DSH 启动 2.5 秒后会把已安装、已同意协议、且没在跑的 SnowLuma 拉起来。
设置里还没写目录的话，它会先找本机已有的安装：正在运行的实例优先；带有效 `consent.json`（或 DSH 之前启动记录）的目录会直接接管（写配置并拉起），
没有同意记录的只把目录填进设置，等主人自己勾——第一次接受协议永远不替主人点。
安全起见，后台只监听 `127.0.0.1`，不要把 OneBot / 5099 开到局域网。

### 插件实际用到的接口（换后端时照这个核对）

```
send_private_msg            发私聊
send_group_msg              发群消息
get_login_info              看登录的 QQ 是哪个（设置页显示"✓ 连着的 QQ"）
get_friend_msg_history      收私聊（QQ → DSH）
get_group_msg_history       收群消息（QQ → DSH）
get_forward_msg             展开合并转发（聊天记录）
```

只要你的后端把这 7 个接口开在 HTTP 上，插件就能用。没有 `get_forward_msg` 时其它功能照常，只是合并转发只剩占位。

另外，想要戳一戳就再开一个 **HTTP 上报（httpClient）** 指向 `http://127.0.0.1:19388/dsh-qq/event`；
不开只少戳一戳，上面的聊天功能不受影响。

### 用 NapCat 也行（进阶，不在一键安装里）

插件只认 OneBot 11 HTTP，所以 NapCat 这类后端同样能接，只是要自己装：

1. 从 [NapCat 的 Releases](https://github.com/NapNeko/NapCatQQ/releases) 下 Windows 版并启动
2. 在它弹出的网页后台里扫码登录你要用的 QQ 号
3. 确认 **HTTP 服务**开着、端口和设置页显示的 OneBot 地址一致
4. 想要戳一戳，再按上面的「戳一戳」一节加一个 HTTP 上报（httpClient）
5. 回到设置页点「重新检测」

> ⚠️ 只有 **HTTP** 模式够用（插件不连 WebSocket）。开了 WS 但没开 HTTP 的话，插件连不上。

### 其它

- 桌面只留这个后端 + 本插件 + DSH。
- 她像没看见图：先看设置页「她在群里的状态」的「看图」一行。回复或判断模型如果标着「仅文本 / 看不到图」，就到模型下拉里换成支持图片输入的（如 `deepseek-flash`）；日志里出现「纯文本模型」也是同一件事。
- 翻旧记录另外依赖 Tulpa 跑着、它的 MCP 数据服务开着（默认 `http://127.0.0.1:18777/mcp`）。不装 Tulpa 只是没有旧记录可翻，`DSH ↔ QQ` 两半和社交模式照常能用。
- `POST /receive` 路由还留着，是想用别的方式（比如另一个程序）把 QQ 消息灌进来的备用入口，不依赖它也能跑。
