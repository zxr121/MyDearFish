## 0.2.0 — 2026-10-19（dsh-bili-subagent）

> 本仓库是 [c1overzz/dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll) 的改版（fork），
> 基于它的 **0.1.10**，沿用 MIT 许可并保留原作者署名。

**改版主线：从「插件自己刷」改成「伙伴派子代理去刷」**

- ⭐ **核心流程重做**：插件不再自己起一个 headless 会话去刷，而是替伙伴**派出一个子代理**——
  子代理只负责看（搜视频 → 扫标题 → 看简介 → 读整段字幕 → 翻评论区），产出一份**给伙伴看的内部报告**
  （标题 / BV号 / 讲了什么 / 为什么值得 / 评论区反响）。
  再由伙伴用自己的口吻决定怎么告诉用户：**公开评论只写一两句勾人，私信可以详细**。
- ✅ 新增 `bili_scan` 工具：`ctx.subagents.startActivation({ provider: 'spawn', … })`，
  子代理的 provider / 模型在设置页里选，可以指到便宜或免费的中转，不占官方额度。
  支持"没字幕就跳过"，报告同时追加写入 `<家>/out/<日期>.md`。
- 🗑 删掉 `bili_run` —— 它和 `bili_scan` 重复，会把模型带回旧的 headless 路子。
- ✅ **自动刷可以指定会话**：优先用设置里选的那个，其次是最近聊过的，都没有才临时新建一个
  （用完 30 秒 / 最迟 20 分钟自动释放）。
- ✅ **投递拆成两条**：「公开评论 @」和「私信」可以同时开；两者都开时，**这一轮还没发评论会拦住私信**
  （实测模型会习惯性跳过评论，只能硬拦；评论"调过就算"，失败也解锁，不会卡死）。
- ✅ **提示词可改**：称呼、子代理的流程与人设都在设置页里直接编辑，不用改代码。
- ✅ **新增「挑什么样的」两道硬门槛**：最低播放量、至少发布几天。
  过滤做在 `bili_search` **工具层**——不达标的视频根本不返回给子代理；有门槛时自动多抓 4 倍再筛、
  截回请求条数，避免筛完一条不剩。（内置 MCP 的搜索结果这版补上了 `pubdate` 字段，"至少几天"才有依据。）
- ✅ **额度口径统一**：`每天最多自动刷几轮`（原标签写"挑几条"，实际数的是轮次）；面板显示
  「今天已自动刷 X / N 轮」，**手动跑不占额度**；并修掉 `count` 与 `picked` 长期不同步的问题。
  `bili_status` 只回三个清楚的数字：`autoRoundsToday` / `autoRoundsLeft` / `videosToday`。
- ✅ **自动刷改成「窗口内按间隔轮转」**：以前每个窗口每天只跑一次（`windows[key]` 打勾）⇒ 一天最多 3 轮，
  `perDay` 填 5 永远用不满。现在新增 `gapHours`（两轮之间至少隔几小时，默认 3），窗口里一轮一轮轮转、
  直到额度用完；**投递失败会把额度和间隔一起退回**，下个周期还能重试。
- 🗑 **去掉用不到的模块**：本地转写（ASR）、回复楼中楼、headless / overlay、一键升级 / 检查更新、
  关注关键词、工作区、群答疑手册、`tools/` 开发脚本。
- 🔧 **修配置读写**：
  - `loadCfg` 改读 DSH 原生设置的**生效值**（`row.value`），不再用 apply 的 config 参数 —— 治"设置改了弹回"；
  - `/config` 的白名单改成按 `DEFAULTS` 动态生成 —— 以前写死，新增字段存不下；
  - `pythonPath` 落在 `python` 时，自动退回插件自己的 venv。
- 🤝 **不再自己删子代理记录**：留着能回看当时刷了什么，也避免误删别人的会话。
- ⚠️ 已知小缺陷：自动刷的额度在**触发时**就 +1，那一轮失败也占额度。

**修（都是用户报的，两条来自 GitHub issue）**

### 并入的修复批（PR #4 · @ProgramerNoob · 17 个文件、+577/−142）

照着一份完整代码审查逐条过了一遍。界面没变，修的都是「看得见的行为」。

**修**
- ⭐⭐ **值班轮以前能拿到整台工具**：插件把内置的 Python MCP 整个挂给了它 ⇒ 「没开自动评论就不许发评论」那道闸
  只在**工具参数**那一层拦着，模型换个写法就能绕过去。现在改成**按名单注册**：那一轮只拿得到**四个只读工具**
  （搜视频 / 读字幕 / 读评论 / 看视频信息），**开了「自动评论」或「回复评论」才多给一个**「发评论」；
  上传视频、发动态、私信、抓全站那些**根本不注册** —— 模型连它们的名字都看不到（名单走 `BILI_MCP_TOOLS` 下发）。
- ⭐ **发评论的回执以前不带 `rpid`**：判重表要记它、评论复核要靠它去查，可工具把回执丢了、只回一句「发送成功」
  ⇒ **复核永远查不到自己那条评论**，表里也只能空着。现在回执会带 `rpid`（回复别人时连 `root` 一起），

- ⭐ **抓评论出错不再装成「这条视频 0 条评论」**：风控（`-412`）、网络错以前被吞掉，日报里就直接当没评论 ⇒
  现在错误会原样记下来，跟「真没有评论」分得清。
- ⭐ **「每天最多挑几条」以前根本不生效**：这一天到底挑了几条从来没人记 ⇒ 上限永远不触发，中午晚上各跑一轮、
  写进同一份日报还可能互相覆盖。现在按**当天报告里数出来的条数**算（取它和账本里的较大值），到量就不跑；
  提示词里也会写「今天已经挑过 N 条，这一轮最多再挑 M 条」+「有就追加到末尾，别覆盖」。
- ⭐ **配额不再把「提到过的视频」算成「挑中的」**（复查时发现的坑）：报告里还会出现**没挑中**的视频号 ——
  「因无字幕跳过 N 条」那行、评论区里别人问起的视频 —— 全按视频号数的话，一天只要提到 5 个就把当天的额度吃光，

  （漏写当成没挑中、给提到过的视频加上标题则当成挑中 —— 两种情况都会在日志里显形）。
- ⭐ **章程升级不再「改一次管一辈子」**：以前家里那份比插件里的新就一直用家里的 ⇒ 你改过一次，
  以后插件带的规则（防注入、「空也是一种结果」这些）就再也进不来。现在记了账（`charter.sha256`）：
