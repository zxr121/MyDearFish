# 给 AI 助手看的（本仓库 = 一个 DSH 插件）

`dsh-bili-subagent`（中文名「**刷B站（子代理版）**」）：

> 它不再自己"跑一轮写日报"，而是**替用户的 AI 伙伴派出一个子代理**去刷 B站 ——
> 子代理只负责看（搜 / 读字幕 / 翻评论），写一份**给伙伴看的内部报告**；
> 再由伙伴用自己的口吻发**公开评论 @ 用户** 和/或 **私信**。
>
> 本仓库是 [c1overzz/dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll) 的改版（fork，MIT）。

## 帮用户安装时，按这个顺序

1. **前提**：机器上有 `Python 3.10+` **或** `uv`（有一个即可）。
   两个都没有也**不用先让用户装** —— 点「装主依赖」时插件会**自己下一份 `uv`** 到自己的家目录
   （免管理员、不用 PATH；直连 GitHub → 国内加速 → PyPI 镜像，下载完核对官方 sha256）。
   · ⚠️ 杀软拦了这次下载：把 `%USERPROFILE%\.dsh\bili-duty\bin\` 加白，或让用户自己装 uv / Python 3.10+。
   · 都下不动：手动放一份 `uv.exe` 到 `<家目录>\bin\`，插件会用那一份、跳过下载。
2. **装插件**：
   ```bash
   dsh plugin --profile desktop add github:Yuuyuko-uu/dsh-bili-subagent
   ```
   （本版暂未上 npm；上架后可简写成 `dsh plugin add dsh-bili-subagent`。）
   · ⚠️ 需要 **DSH ≥ `0.1.7-rc.1`**，版本不满足会被**静默跳过**（装了跟没装一样，不报错）。
3. ⚠️ **提醒用户重启一次 dsh**（必须，bundle 层要重启才组装）。
4. 让用户进 **设置 → 刷B站**：点「**装主依赖**」→ 点「**扫码登录**」
   （手机 B站 扫码，**确认时选「记住我 / 长期」**）。
   装完可以用「**测一下**」自检：真跑一次登录检查 + 一次搜索。
5. **别擅自打开「自动评论并 @ 你」** —— 那是拿用户的号公开说话，必须由用户自己决定"@ 谁"。
6. 想让它省心，帮用户看一眼这两项：**派子代理刷的模型**（指到便宜/免费的中转就不花官方额度）、
   **自动刷在哪个会话**（不选会自动挑最近聊过的）。

## 常见问题（用户真会撞上的）

- **设置页里根本不出现「刷B站」** → DSH 版本不满足（静默跳过）或插件没重启。先确认版本，再重启。
- **扫码时一直不出二维码 / `No module named mcp`** → 家目录里 `pythonPath` 落成了 `python`。
  点一次「装主依赖」，它会自动指回插件自己的 venv。
- **自动刷没动静** → 看 `<家目录>/duty.log`：写着「**目标会话现在没醒着**」就是目标会话睡着了，
  先去那个会话说句话，让它醒着。
- **伙伴只发私信、不发评论** → 看设置里的「投递方式」和「每轮最多发几条评论」；
  两者都开时，**这一轮没发评论会被拦住私信**（这是故意的）。
- **评论发不出去 / 被吞** → B站 风控。新号、发言太频繁、内容带链接都可能被吞；换条内容、错开时间。

## 仓库结构（改代码时看这里）

- `index.js` —— 宿主半端：12 个工具 + 谷时定时器 + HTTP 接口 + 配置（`config.json` 与 DSH 原生设置**逐字段对账**）
- `client.js` —— 浏览器半端：设置页（注册在 `settings.section`）
- `lib/` —— 状态目录 / 极小的 MCP stdio 客户端 / 扫码登录 / `hostdeps.mjs`（从宿主树取 `@deepseek-ai/*`）/ `verify.mjs`（评论发出后复核）
- `vendor/bilibili-mcp/` —— 内置的 Python MCP（MIT，AGI_Ananas）
- `prompts/duty.md` —— 上游留下的值班章程，**本版已不再使用**（提示词改在设置页里编辑）

## 约定

- 配置与运行数据都在用户的 `$DSH_HOME/bili-duty/`，**不写进插件包目录**
- 谷时窗口按 DeepSeek 官方口径：工作日 9–12 / 14–18 是高峰，其余（含周末）都是谷时

## 改这个插件时注意

- 工具定义（名字 / 描述 / 参数）**一改就作废 DSH 的前缀缓存**，大会话等于重算一遍，很贵。
  改代码逻辑、改提示词、改设置都**不影响**缓存。
- 别一边跑 dsh 一边改 `node_modules` 里的插件文件 —— 会触发 HMR 重载、把工具表抖一遍。
  改完再让用户重启。
